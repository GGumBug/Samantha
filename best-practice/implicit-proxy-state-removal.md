# 암묵적 대리자 상태 제거 — 읽기 지점 전수 조사

상태·플래그·접합부를 걷어낼 때 grep 대상은 **쓰기 지점이 아니라 읽기 지점**이다. 제거 대상은 이름이 표방하는 사실 하나만 나르지 않는다 — 원래 목적 외 독자가 붙어 있는 것이 **기본값**이고, 그 독자들이 무엇을 읽고 있었는지 세지 않으면 제거는 조용히 절반만 끝난다.

Double Down 카드 연출 채널 이관(2026-08-04) 한 세션에서 **같은 계급의 누락이 3회 반복**, 그중 2회가 사용자 재현에서야 발견됐다.

## 1. 왜 쓰기 지점 grep 으로는 안 잡히는가

제거 대상이 나르던 것이 **값**이면 컴파일러가 잡고, **보장**이면 아무도 안 잡는다.

| 나르던 것 | 제거 시 증상 | 탐지 수단 |
|---|---|---|
| 값 (필드·프로퍼티 참조) | 컴파일 에러 | 컴파일러 — 자동 |
| 부수효과 (대입·이벤트 발행) | 상태 불일치 | 부수효과 매트릭스 ([overload-semantic-equivalence.md](overload-semantic-equivalence.md)) |
| **판정 조건** (다른 코드가 이 플래그를 "지금 X 중"으로 읽음) | 시각·논리 회귀 | **읽기 지점 전수 grep — 유일** |
| **보장** (순서·배타·정지가 부작용으로 공짜였음) | 시각 회귀, 재현율 낮음 | 읽기 지점 grep 으로도 안 잡힘 — §3 2회 사례 |

아래 두 줄은 컴파일·테스트·정적 grep 어디에도 안 걸린다.

- 뒤집기가 추종을 얼려서 "뒤집기 끝날 때까지 이동 정지"가 **공짜로** 보장됐다
- 감독이 트랜스폼을 쥐고 있다는 사실이 "지금 연출 중이니 다른 카드 위에 그려라"로 **읽히고** 있었다

## 2. 독자 의미 분류표 (의무 산출물)

제거 대상 심볼을 **이름만** grep 하고, 결과 각 행을 아래 표로 분류한다. `\b_ownsTransform\b` 처럼 값 비교 패턴(`== true`)은 검색하지 말 것 — 읽는 형태는 caller 마다 다르다.

| 읽는 곳 | 무엇을 판정하려고 읽는가 | 이관 후 대체 채널 | 상태 |
|---|---|---|---|
| 정렬 승격 판정 | "지금 연출 중" | `_flipActive` | 대체됨 |
| 추종 갱신 가드 | "지금 감독이 소유" | 합성 지점 단일화로 소멸 | 소멸 |
| (안무) 이동 시작 조건 | "뒤집기 끝났는가" | **없음** | **대체 없음** |

**"대체 없음" 행이 0이 될 때까지 이관은 미완료**로 취급한다. 대체가 없는데 제거를 진행해야 한다면, 그 보장을 **명시적으로 다시 만들어** 넣는 것이 이관의 일부다(예: 이동 시작 전 뒤집기 완료 대기를 코드로 표현).

## 3. 실측 3회 — 같은 계급의 누락

소유권 플래그(`_ownsTransform`)는 소유권 표시가 아니라 여러 사실의 **암묵적 대리자**였다.

| 회차 | 대리하던 사실 | 발견 시점 | 결과 |
|---|---|---|---|
| 1 | 정렬 승격 판정 ("연출 중이니 위에 그려라") | 이관 **전** 사전 조사 | `_flipActive` 로 복원 — 무사고 |
| 2 | **안무 순서** (뒤집기가 추종을 얼려 이동 정지 보장) | 사용자 재현 | 카드가 뒤집히며 미끄러지는 회귀 (`dcfb424`) |
| 3 | 뜸(`_riseActive`)이 정렬 승격 + 그림자 들림 **두 판정식에서 동시 누락** | 사용자 재현 | 카드가 더미 뒤로 숨는 회귀 (`7f65ab0`) |

1회는 사전에 잡혔고 2·3회는 못 잡혔다. 차이는 난이도가 아니라 **조사 축**이다 — 1회는 "이 플래그를 누가 읽나"를 물었고, 2·3회는 묻지 않았다.

## 4. 판정식 축 — 상태가 아니라 조건 집합을 센다

3회 사례는 형태가 조금 다르다. 제거된 플래그의 독자가 아니라, **새 채널이 기존 판정식의 조건 집합에 편입되지 못한** 경우다. 규율은 동일하다 — 방향만 뒤집는다.

- **역방향 grep 의무**: 새 채널(`_riseActive` 등)을 도입하면, 옛 플래그를 읽던 **판정식 이름으로** grep 해 조건 집합을 나열하고 새 채널의 편입 여부를 행마다 표시
- 판정식이 여러 개면 **하나만 고치고 끝내지 않는다** — 3회 사례는 정렬 승격만 고치고 그림자 들림을 빠뜨려 증상이 절반만 사라졌다
- 판정식은 대개 `if` 한 줄이라 diff 에서 눈에 안 띈다. 표로 강제 나열하지 않으면 육안 검토로는 통과한다

## 5. 목록·컬렉션 제거에도 같은 판정

제거 대상이 플래그가 아니라 **목록**이어도 동일하다. `_live` 목록을 걷어낼 때 그 목록에는 계약 위반 진단이 얹혀 있었다 — 원래 목적(생존 인스턴스 추적)과 무관한 독자다.

**대체 논증 없는 제거는 진단 능력의 조용한 상실**이다. 제거 조건은 "안 쓰는 것 같다"가 아니라 **"대체재가 더 정확하다"의 논증**:

> 뷰의 재진입 경고가 같은 계약 위반을 **더 이른 시점에, 더 좁은 범위로** 보고한다 → 목록 기반 진단은 잉여

## 종료 게이트

- [ ] 제거 대상 심볼을 **이름만** grep (값 비교 패턴 금지)
- [ ] 결과 전 행을 독자 의미 분류표로 정리 — "대체 없음" 행 **0건**
- [ ] 제거 대상이 나르던 것 중 **보장(순서·배타·정지)** 이 있는지 별도 자문 — 값·부수효과만 세면 §3 2회 사례가 재발
- [ ] 새 채널 도입 시 옛 플래그를 읽던 **판정식 전수**에 편입 여부 표시 (§4)
- [ ] 진단 목적 독자는 **대체재가 더 정확함을 논증한 뒤** 제거 (§5)
