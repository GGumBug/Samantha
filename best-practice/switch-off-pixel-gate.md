# 스위치로 갈리는 화면 변경의 회귀 게이트

데이터 스위치로 켜고 끄는 기능을 화면에 붙이면, 꺼진 런은 편집 전과 한 픽셀도 달라지면 안 된다.
이 성질은 시험 개수로는 증명되지 않는다. 같은 탐침으로 찍은 캡처를 대조해야 증명된다.
Double Down 「밑천 내기」 2단계 화면(2026-10-06)에서 화면 5개를 이 방법으로 판정했다.

## 1. 절차

1. **탐침부터 검증한다.** 같은 상태를 두 번 찍어 다른 픽셀이 0인지 본다.
   0이 아니면 탐침이 비결정론이다(연출 진행 중, 시간 의존). 그 위의 대조는 의미가 없다.
2. **편집 전에 꺼진 상태를 찍어 둔다.** 편집이 시작되면 기준선은 워크트리를 따로 꺼내야만 다시 만들 수 있다.
3. **편집 뒤 같은 탐침으로 다시 찍는다.** 합격 기준은 다른 픽셀 수 0이다. "거의 같다"는 기준이 아니다.
4. **켜진 쪽은 따로 판정한다.** 무엇이 어디에 보여야 하는지는 [evaluation.md](../.claude/rules/evaluation.md)의 시각 검증 단위로 적는다.

1번은 뮤테이션 검증과 같은 계급이다. 계측기가 판별력을 갖는지 먼저 확인하고 나서 그 판정을 믿는다.

## 2. 탐침은 실제 진입 경로를 지나야 한다

정산 창 패널은 화면 아래로 이어지는 서랍이다. 제자리가 y=-330이고 보이는 높이는 약 750이다.
새 줄 셋을 더하자 확인 버튼이 화면 밖으로 밀렸다.

첫 캡처 탐침은 패널 위치를 손으로 놓았다. 그 탐침은 진입 경로가 계산하는 제자리를 보지 못한다.
결함이 있어도 손으로 놓은 위치가 그 계산을 대신하므로 화면이 맞아 보일 수 있다.
다음 탐침은 실제 경로(`ShowAsync`)를 지나게 하고 미끄럼 지속 시간만 0으로 두었다.

규칙은 하나다. **결정론은 연출 시간을 0으로 만들어 얻고, 상태를 손으로 놓아 얻지 않는다.**
시험이 배포 에셋을 불러오지 않으면 설정 축이 빠지는 것과 같은 계급의 문제다([coincidental-pass.md](coincidental-pass.md) §2).

## 3. 자라는 컨테이너의 기하는 열린 식으로

서랍의 제자리를 상수로 다시 적으면 줄이 하나 더 늘어나는 날 같은 결함이 돌아온다.
처방은 식이다. 켜진 줄마다 (rect 높이 + `VerticalLayoutGroup` 간격)을 더하고 그 합만큼 제자리를 올린다.

이 식에는 덤이 있다. 꺼진 런은 켜진 줄이 없어 합이 0이다. 그래서 §1의 픽셀 0 게이트를 식 자체가 보장한다.
상수 보정을 넣었다면 꺼진 쪽을 위한 분기가 따로 필요했다.

판별 질문은 [open-ended-range.md](open-ended-range.md)와 같다. "줄이 지금의 두 배면 무엇이 화면 밖으로 나가는가."

## 4. 실측

| 항목 | 결과 |
|---|---|
| 탐침 결정론(같은 상태 2회) | 다른 픽셀 0 |
| 꺼진 런, 편집 전후 대조 | 화면 5개 모두 다른 픽셀 0 |
| 서랍 제자리 | 상수 y=-330에서 켜진 줄의 높이·간격 합으로 바꿈 |

## 종료 게이트

- [ ] 같은 상태를 2회 찍어 다른 픽셀 0을 확인했는가
- [ ] 편집 전에 꺼진 상태 기준선을 찍었는가
- [ ] 편집 뒤 꺼진 상태가 화면마다 다른 픽셀 0인가
- [ ] 탐침이 실제 진입 경로를 지나는가 (위치를 손으로 놓지 않고 연출 시간만 0)
- [ ] 내용으로 자라는 컨테이너의 기하가 켜진 항목에서 파생되는가
