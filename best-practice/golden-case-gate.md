# Golden Case 종단 동결 게이트 — 파이프라인 종단값 손계산 동결

다단계 계산 파이프라인(채점 → 판정 → 게이트 → 정산 등)의 단계 게이트에서, 단위 테스트와 **별도로** 전 파이프라인을 관통하는 Golden Case 를 두고 **종단값을 손계산으로 동결**하는 패턴. Slice A 고스톱 정산 파이프라인(2026-07-20, 카드 18 게이트)에서 실측.

## 왜 종단값인가 (중간값 아님)

- 단위 테스트는 **부품 정확성**만 보증 — 부품 간 연결(순서, 소비 시점, 전달 형식)의 회귀는 못 잡는다
- 중간값 동결은 해당 단계까지만 감지 — **종단값 동결은 어느 축이 회귀해도 한 케이스가 감지**
- 기대값은 코드 재실행이 아니라 **손계산**으로 산출 — 구현을 기대값의 원천으로 쓰면 회귀 감지 불가 (자기 평가)

## 구성 원칙 4가지

1. **커버리지 감사 표 선행** — 케이스 선정 전에 축×판정 표(본 사례: 7축×판정)를 만들어 각 Golden Case 가 어느 축을 통과하는지 명시. 감사 표 없이 케이스를 고르면 축 누락.
2. **종단값 손계산 동결** — 파이프라인 입력(패 구성 등)부터 종단 출력(칩 정산액)까지 손계산 유도 과정을 주석/문서로 남기고 값을 동결
3. **대칭성 케이스** — 좌석 스왑 같은 대칭 변환 후 결과 대칭성 단언 (하드코딩된 좌석/플레이어 인덱스 회귀 감지)
4. **재계산 결정론** — 같은 입력 2회 계산 결과 동일 단언 (내부 상태 오염·소비성 config 이중 소비 감지)

실측: 단위 83케이스 + 종단 Golden Case 4케이스(채점 → 박 판정 → 고 게이트 통과 단언 → 고박 → 정산 종단값 동결). 중간 단계의 게이트 통과 여부도 단언에 포함해 "어디서 깨졌는지" 진단 가능하게 유지.

## 룰 모호점 확정 루프 (동결 보류 → 사용자 확정 → 기록)

Golden Case 작성 중 검증자가 **룰 자체의 모호점**을 발견하면(예: 피박 패자 피 0장 성립 여부 — Ruleset 문언 vs 전통 변형) 코드 형태로 디자인 의도를 단정하지 않는다 (헌법 Step 2). 절차:

1. **해당 경계의 동결 케이스를 의도적으로 보류** — 추측값으로 동결하면 잘못된 룰이 테스트로 고착
2. **사용자에게 옵션 제시·확정** — 각 해석의 결과 차이를 구체 예시로 제시
3. **Ruleset 변경 기록 항목 추가** — 확정된 해석을 룰 문서에 기록 (구두 확정은 휘발)
4. **확정 후 동결 케이스 추가** — 보류했던 경계를 케이스로 박제

실사례(2026-07-20): 피박 패자 피 0장 — 옵션 A(문언 유지) 확정 → Ruleset 변경 기록 + 경계 동결 케이스 추가.

## 게이트 위임 체크리스트

- [ ] 커버리지 감사 표(축×판정) 선행 작성
- [ ] 기대값 산출 방식이 손계산인지 확인 (구현 재실행 금지)
- [ ] 대칭성·재계산 결정론 케이스 포함
- [ ] 룰 모호점 발견 시 동결 보류 → 사용자 확정 → 기록 → 동결 순서 준수
