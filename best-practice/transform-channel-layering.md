# 표시 계층 배치 — 같은 축이라도 크기가 종류를 바꾼다

뷰 오브젝트를 루트/흔들림/기울기처럼 **여러 트랜스폼 층**으로 나누고 "지속 상태는 루트, 과도 연출은 흔들림 층"처럼 배치 규칙을 정해 두는 설계는 흔하다. 규칙이 코드 주석에 적혀 있어도 새 오프셋을 얹는 순간 **표면적 유사성이 명시된 규칙을 이긴다**. Double Down 택1 배치(2026-08-29) 실측 — 후보 카드를 화면 중앙으로 옮기는 변위를 "펀치 연출과 같은 부가 위치 오프셋"으로 분류해 흔들림 층에 얹었더니, 콜라이더(루트)와 그림자(흔들림 층의 형제)가 따라오지 않아 **호버가 안 먹고 그림자가 카드에서 이탈**했다.

## 1. 오분류의 메커니즘

두 연출은 **같은 축**(위치 오프셋)을 쓴다. 그래서 같은 종류로 보인다. 다른 것은 크기와 지속시간뿐인데, 그 둘이 정확히 **동반자 요구를 뒤집는다**.

| | 펀치·흔들림 | 지속 변위(선택 강조·중앙 정렬) |
|---|---|---|
| 변위 크기 | 몇 픽셀 — 히트박스 내부 | 오브젝트 폭의 몇 배 — 히트박스 밖 |
| 지속시간 | 프레임 단위, 원위치 복귀 | 상태가 끝날 때까지 유지 |
| 콜라이더가 따라와야 하나 | **아니다** — 따라오면 입력 지점이 떨린다 | **그렇다** — 안 따라오면 클릭 불가 |
| 그림자·부착물 | 안 따라와도 티가 안 남 | 안 따라오면 즉시 이탈 |

"콜라이더가 안 따라오는 것"이 펀치에서는 **기능**이고 지속 변위에서는 **결함**이다. 같은 층에 얹는 순간 한쪽은 반드시 틀린다.

## 2. 배치 결정 3문 (새 오프셋을 얹기 전에)

1. **지속시간** — 프레임 단위로 복귀하는가, 상태가 끝날 때까지 남는가
2. **변위 크기** — 히트박스 내부인가, 넘어가는가
3. **동반자** — 콜라이더·그림자·아웃라인·툴팁 앵커·파티클 중 **함께 움직여야 하는 것**을 열거한다

세 답 중 하나라도 기존 채널과 다르면 **다른 종류**다. 기존 층에 얹지 말고 **지속 변위 전용 층을 신설**한다. 층 신설 비용은 트랜스폼 하나이고, 오분류 비용은 입력·연출 회귀 진단이다.

## 3. 층 계약을 문서가 아니라 구조로

주석에 적힌 규칙은 이번처럼 **분류 단계에서 우회된다** — 규칙을 어긴 것이 아니라 새 연출을 잘못된 칸에 넣었기 때문이다. 그래서 처방은 문장 보강이 아니라 층별 계약을 좁히는 쪽이다.

- **층별로 쓰는 API 를 분리** — 흔들림 층은 진폭 상한이 있는 헬퍼만 노출하고 임의 좌표 대입을 막는다
- **동반자를 층에 소속시킨다** — 그림자·툴팁 앵커를 "따라와야 하는 층"의 자식으로 두면 배치 실수가 구조로 차단된다
- **콜라이더는 실제 표시 위치를 따라가는 층에 둔다** — 표시와 입력이 다른 층에 있으면 둘의 동기화가 영구히 사람 책임이 된다

## 4. 검증 — 육안으로는 변위만 보인다

지속 변위를 옮긴 뒤 "위치가 맞는가"만 보면 통과한다. 다음을 별도 항목으로 확인한다([evaluation.md](../.claude/rules/evaluation.md) 시각 검증 단위 명세).

- [ ] 변위 상태에서 **호버·클릭이 먹는가**(콜라이더 추종)
- [ ] 그림자·아웃라인·툴팁 앵커가 **따라왔는가**
- [ ] 변위 중 기존 과도 연출(펀치·흔들림)을 겹쳐도 **둘이 서로 상쇄하지 않는가**
- [ ] 변위 취소·중단 시 **원위치로 복귀**하는가
