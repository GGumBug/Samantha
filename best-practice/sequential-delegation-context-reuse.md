# 동일 에이전트 연속 위임 — SendMessage 재개로 컨텍스트 재사용

연속되는 카드/태스크를 매번 신규 에이전트로 위임하지 않고 **같은 인스턴스에 SendMessage 재개로 이어서 위임**하는 전략. Slice A 개발 보드 카드 13.5~18(2026-07-19~20)에서 실측.

## 실측 사례

- 구현: 카드 14-A → 14-B → 14.5-A → 15-A → 16-A → 17-A 를 **한 Jarvis 인스턴스**로 연속 위임
- 테스트: 카드 14-C → 17-B 를 **한 Sonny 인스턴스**로 연속 위임

효과 3가지:

1. **설계 컨텍스트 보존** — 이전 카드에서 확정한 도메인 규칙·API 결정을 재설명 없이 이어감
2. **산출물 API 일관성** — 패턴 미러가 자연 발생 (신규 인스턴스는 기존 코드 재독 후 다른 스타일을 도입하기 쉬움)
3. **토큰 절약** — 파일 재독·설계 재설명 반복 제거 (신규 프롬프트 대비)

## 판단 기준 — 재개 vs 신규 인스턴스

| 조건 | 선택 |
|------|------|
| 같은 도메인의 연속 카드, 산출물 API 가 연쇄됨 | **재개** (SendMessage) |
| 이전 카드 산출물을 직접 소비/확장하는 작업 | **재개** |
| 도메인 전환 (예: 전투 → UI) | 신규 인스턴스 |
| 독립 감사/검증 — 오염 없는 시각 필요 | 신규 인스턴스 (구현 인스턴스 재사용 금지) |
| 인스턴스 컨텍스트가 비대해져 품질 저하 신호 | 신규 인스턴스 |

## 운영 규칙

- 카드 단위로 보고 받고 재개 — 여러 카드를 한 번에 몰아주면 `maxTurns` 절단 위험 ([unity-delegation.md](../.claude/rules/unity-delegation.md) "단일 에이전트 5개 항목 한계" 준수)
- 독립 감사는 반드시 별도 인스턴스 — 구현 컨텍스트를 이어받은 검증은 자기 평가에 가까워짐 ([evaluation.md](../.claude/rules/evaluation.md) 작성자/검증자 분리)
- 재개 프롬프트에도 작업 범위·범위 외 금지는 매번 명시 — 범위 보존 의무는 재개라고 면제되지 않음
