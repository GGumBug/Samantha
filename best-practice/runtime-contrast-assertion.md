# 런타임 자기 대조 장치 — 파생 표현 vs 권위 상태 불일치 즉시 검출

**테스트가 전부 green 인데 실플레이에서 결함이 나오는 영역**이 있다. 권위 상태(도메인)와 파생 표현(UI·폴드·캐시)이 병존하고, 둘의 동기화가 **시점·이벤트 순서**에 의존할 때다. 이 영역은 단위 테스트가 구조적으로 못 잡는다 — 테스트는 각 부품의 정확성을 보증하지 실플레이의 이벤트 타이밍 조합을 재현하지 않는다.

처방: **런타임에 자기 대조 장치를 미리 심어 둔다.** 파생 표현이 갱신되는 지점에서 권위 상태와 비교하고, 불일치면 `LogError`. Double Down Slice A 카드 27(2026-07-28) 실측.

## 실측 — 3사이클을 초 단위 판정으로 압축

카드 27(Domain Event 표현 어댑터)은 단위 테스트 전부 green 상태로 실플레이에 들어갔고, **폴드 불일치 결함 4종**이 나왔다:

1. 스냅백 시 폴드가 옛 상태로 되돌아감
2. 라운드 종료 시 폴드 미갱신
3. mid-turn 갱신 누락
4. 정체(신원) 미공개 상태가 폴드에 노출

폴드 vs 권위 비교 `LogError` 를 런타임에 심어 둔 설계 덕에, **"재현 → 로그 확인 → 원인 지목"이 초 단위로 끝나 3사이클이 압축**됐다. 장치가 없었다면 각 결함마다 진단 로그 삽입 → 재현 요청 → 수집 → 분석의 4단계([evidence-based-debugging.md](evidence-based-debugging.md))를 4회 반복해야 했다.

## 설치 규칙

**어디에**: 파생 표현이 **갱신을 마친 직후**(갱신 함수의 말미). 갱신 전에 비교하면 정상적인 과도 상태를 오탐한다.

**무엇을**: 권위 상태에서 파생 표현을 **다시 계산해 비교**한다. 파생 표현끼리 비교하면 둘 다 틀렸을 때 침묵한다.

**어떻게**:

- `LogError` 로 낸다 — `LogWarning` 은 콘솔 노이즈에 묻힌다. 불일치는 **정의상 버그**이므로 경고가 아니다
- 메시지에 **양쪽 값을 모두 출력** — "불일치 발생"만으로는 어느 쪽이 틀렸는지 모른다
- **에디터/개발 빌드 전용 가드**로 감싼다 (`#if UNITY_EDITOR || DEVELOPMENT_BUILD`) — 재계산 비용을 릴리스에 지불하지 않는다. 가드 구분 기준: [unity-editor-only-guards.md](unity-editor-only-guards.md)

## 적용 판단 — 언제 심고 언제 안 심는가

| 조건 | 판단 |
|------|------|
| 권위 상태가 **명확히 하나** 있고 파생 표현이 그로부터 계산 가능 | **심는다** |
| 동기화가 이벤트 순서·시점에 의존 (UI 미러, 캐시, 스냅백/롤백) | **심는다** |
| 재계산 비용이 원래 계산과 **같은 자릿수** | 심는다 (개발 빌드 한정이므로 감당 가능) |
| 권위 상태가 없고 표현 자체가 SoT | 안 심는다 — 비교 대상이 없다 |
| 재계산이 원본보다 훨씬 비싼 경우 | 프레임마다 대신 **상태 전이 시점에만** 비교 |

**과용 금지**: 모든 파생 값에 대조를 거는 건 오버엔지니어링. 대상은 **불일치가 사용자에게 보이는 표현**(화면·저장·네트워크 송신)으로 한정한다.

## 왜 테스트로 대체되지 않는가

- 단위 테스트는 **부품 정확성** 보증 — 부품 간 이벤트 순서·시점 조합은 실플레이에서만 발생
- 대조 장치는 **실플레이 자체를 테스트 러너로 만든다** — 사용자가 손으로 만드는 조합이 곧 케이스
- 다만 대조 장치는 **감지**만 한다. 감지된 케이스는 단위 테스트/Golden Case 로 승격해 회귀를 고정한다 ([golden-case-gate.md](golden-case-gate.md))
