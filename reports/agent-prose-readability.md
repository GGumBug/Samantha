# 에이전트 산문 가독성 — 주석·커밋이 협업을 방해하는 구조

에이전트가 쓴 주석과 커밋 메시지가 길고 장황하며 기계가 쓴 것처럼 읽히는 문제의 원인 분석과 처방. 측정은 `tools/prose-audit.py`로 재현한다.

[← 저장소 루트로](../README.md) · [한국어 문체 분석은 별도 보고서](korean-prose-style.md)

---

## 요약

문제는 문체 취향이 아니라 **전달 실패**다. 2026-08-13에 "주석·커밋을 간결하게"라는 지침이 박제됐지만 그 지침이 놓인 곳은 메인 세션 memory 하나였다. 정작 주석과 커밋을 쓰는 주체는 그 memory를 볼 수 없다. Jarvis·Ava·Sonny·TARS 에이전트 정의와 `context: fork`로 실행되는 `/commit` 스킬이 그렇다. 지침은 도달한 적이 없고, 그 사이 장황함은 세 달 연속 증가했다.

| 지표 | 2026-07 | 2026-08 | 2026-09 |
|---|---:|---:|---:|
| 새로 추가된 `.cs` 줄 중 주석 비율 | 18.4% | 30.1% | 36.9% |
| 커밋 제목에 유형 접두 사용 | 89% | 85% | 43% |

지침이 생긴 달(8월)을 기준으로 **개선이 아니라 악화**했다. memory 파일 자신이 이 결과를 예측해 두었다. "기본값이 장황함이라 매번 지시하지 않으면 되돌아간다."

## 2. 원인 — 네 가지 구조적 요인

### 원인 A. 근거를 둘 곳이 주석뿐이다

헌법 §0은 *"원칙대로 했다가 자체 정당화가 될 수 없다. 항상 왜 이 비용을 지불했는가가 함께 설명되어야 한다"* 를 요구한다. 옳은 요구다. 그러나 그 설명이 **어디로 가야 하는지**를 정한 규칙이 없다. `best-practice/`에 57개 문서 5,032줄이 이미 있는데도 라우팅 규칙이 없으니 기본 목적지가 주석이 된다. 요구는 상시적이고 목적지는 무제한이므로 결과는 단조 증가다.

### 원인 B. 지침이 작성자에게 도달하지 않는다

| 전달 채널 | 간결성 지침 포함 여부 |
|---|---|
| `CLAUDE.md` (항상 주입) | 없음 |
| `.claude/rules/*.md` (Glob 자동 주입, 6개 1,137줄) | 없음 |
| `.claude/agents/*.md` (Jarvis·Ava·Sonny·TARS·Samantha) | 없음 |
| `/commit` 스킬 (`context: fork`) | 길이 상한 없음 |
| 메인 세션 memory | **있음 (유일)** |

`/commit` 스킬은 스스로 "격리된 fork 컨텍스트에서 실행되어 호출한 대화의 맥락을 볼 수 없다"고 적어 두었다. memory에 박제한 규칙이 커밋 작성자에게 도달할 경로는 처음부터 존재하지 않았다.

### 원인 C. 상한이 없는 "왜를 써라"

`/commit` 스킬은 제목에 50자 상한을 두고 그 항목만 100% 지켜졌다. 반면 본문에는 "설계 근거·트레이드오프·거부한 대안을"이라고만 적혀 있고 상한이 없다. 그 항목은 88%가 이탈했다. **같은 문서 안에서 숫자가 있는 규칙은 지켜졌고 없는 규칙은 무너졌다.** 주석에는 상한이 애초에 없다.

### 원인 D. 은유가 식별자를 밀어냈다

"보너스 카드도 손끝을 따라 눕는다", "매대의 보너스 카드가 값을 말한다" 같은 제목은 도메인 은유로 일관되고 읽는 맛이 있다. 문제는 **은유가 식별자 자리를 차지했다**는 점이다. 협업자와 도구(`git log --grep`, `git bisect`, 코드 리뷰, 릴리스 노트)는 식별자로 색인한다. 은유는 그 색인을 만들지 않는다. 자연어 어휘("문다", "조용히", "자리")가 커밋 본문 150개에서 각각 50·48·156회 반복되는 동안 타입 이름은 사라졌다.

## 3. 외부 연구가 말하는 기준선

- **What과 Why는 둘 다 필요하다.** ICSE 2022의 커밋 메시지 분류 연구는 좋은 메시지를 "무엇을 바꿨는가"와 "왜 바꿨는가"의 합으로 정의한다. 실제 프로젝트 메시지의 약 44%에 개선 여지가 있다고 보고했다. 흔한 결함은 **Why 누락**이다. 이 저장소는 정확히 반대로 과적합했다. Why가 넘치고 What이 없다.
- **커밋 메시지 품질은 결함과 상관이 있다.** ICSE 2023 연구는 메시지 품질과 결함 경향의 연관을 보고했다. 코드-주석 불일치를 다룬 대규모 연구는 불일치 변경이 버그 유발 커밋으로 이어질 확률이 약 1.5배라고 보고한다. 주석이 길수록 코드와 어긋날 표면적이 넓어진다. 66줄짜리 클래스 doc은 그 자체가 부채다.
- **과한 주석은 '냄새'로 분류된다.** EMSE 2023의 인라인 주석 냄새 분류는 11종을 제시하며 장황·중복·의도 불일치를 포함한다. 주석이 많다고 품질이 오르지 않는다.
- **LLM 산문은 구조적으로 길다.** 개발자-LLM 대화 연구는 LLM 응답이 사람이 쓴 Stack Overflow 답변보다 평균 2.4배 길다고 보고한다. 장황함은 이 에이전트의 개성이 아니라 **모델의 기본값**이며, 명시적 상한 없이는 되돌아온다.

## 4. 처방

### 4-1. 근거 라우팅 3단 (원인 A 해결)

근거를 쓰지 말라는 것이 아니라 **목적지를 정한다**.

| 근거의 크기 | 목적지 |
|---|---|
| 코드가 말할 수 있다 | 이름·타입·테스트로 말한다. 주석 0줄 |
| 한두 줄로 끝난다 | 주석 1~3줄 |
| 그 이상 | `best-practice/` 또는 `reports/` 문서 + 주석에 **링크 한 줄** |

판별 질문 하나: **"이 설명이 6개월 뒤에도 코드와 함께 갱신될 것인가?"** 아니라면 문서로 뺀다.

### 4-2. 숫자 상한 (원인 C 해결)

| 대상 | 상한 |
|---|---|
| 타입 doc | 6줄 |
| 멤버 doc | 3줄 |
| 인라인 주석 | 2줄 |
| `[Tooltip]` | 80자, 태그 금지 |
| 주석 내 `<b>` | 0 |
| 커밋 제목 | 50자 + **바뀐 타입/파일 이름 1개 필수** |
| 커밋 본문 | 6줄 (불릿 3~4개), 그 이상은 문서 링크 |

### 4-3. 전달 채널 교정 (원인 B 해결)

지침을 `.claude/rules/prose-style.md`로 만들고 `# Glob:` 헤더를 붙인다. Glob 규칙은 해당 확장자를 편집할 때 **모든 에이전트 컨텍스트에 자동 주입**된다. memory에는 없던 경로다. 동시에 `/commit` 스킬 본문에 상한과 식별자 의무를 직접 적는다(fork 컨텍스트에 도달하는 유일한 방법).

## 6. 미검증 항목

- **Unity 인스펙터 툴팁의 리치 텍스트 렌더링**: `[Tooltip]`이 `<b>`를 그대로 노출하는지 실물 확인이 필요하다. 확인 방법은 이렇다. 에디터에서 `BoardLayoutConfig`를 선택하고 아무 필드에 마우스를 올린다. `<b>`가 글자로 보이면 54건이 전부 결함이다.
- **읽기 속도 효과**: 상한 적용 후 리뷰 소요 시간이 실제로 줄어드는지는 다음 카드 작업에서 측정해야 한다. 현재 근거는 검색성(§1-3)과 외부 연구뿐이다.
