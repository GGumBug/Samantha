# Slice A 자동 시뮬레이션 검증 — 1,000 Seed (v2)

카드 25(단계 4 P4). 구현자(카드 23·24)와 분리된 독립 검증자가 수행했다. 코드 수정 없음, 밸런스 파라미터 주입 없음 — v2 기본값 그대로 측정한 실동작 기록이다.

## 1. 실행 조건

| 축 | 값 |
|----|-----|
| ProfileVersion | 2 (`OpponentProfile.Placeholder`) |
| 플레이어 시작 칩 | 1200 (`MatchBalance.Placeholder.PlayerStartChip`) |
| 상대 칩 총량 | 720 (`a1_fish`, 비율 1.67:1) |
| 라운드 상한 | 3 |
| bet_min | 10 / 15 / 23 |
| 시드 범위 | 0..999 (양끝 포함, 1000건) |
| 빌드 | `-c Release`, 경고 0 / 오류 0 |

기본값이 이미 v2라 파라미터 주입은 하지 않았다. 사용한 커맨드:

```
dotnet build Tools/HeadlessSim/HeadlessSim.csproj -c Release
dotnet run --project Tools/HeadlessSim/HeadlessSim.csproj -c Release --no-build -- \
  match --seeds 0..999 --check on --out out/run-a.jsonl
```

JSONL 산출물은 전부 `/out/` 아래에 두었다(`.gitignore` 120행에 등재). 보고서에는 집계만 남긴다.

## 2. 합격 기준 판정

| # | 합격 기준 | 결과 | 판정 |
|---|-----------|------|------|
| 1 | 1,000 Seed 100% 종료 | 완주 1000/1000, 예외 0건, 종료 코드 0 | 통과 |
| 2 | 무한 루프 0건 | 스텝 상한 검사기 위반 0건 | 통과 |
| 3 | 카드 위치/소유권 위반 0건 | 검사기 + 독립 검증 모두 0건 | 통과 |
| 4 | 칩 음수 0건 | 음수 0건, 추가로 칩 총량 1920 보존 1000/1000 | 통과 |
| 5 | 동일 Seed 재실행 일치 + 올인 분포 확보 | SHA256 동일(바이트 단위), 분포 아래 4절 | 통과 |

5항목 전부 통과. `--check on`은 스텝 상한·칩·카드 3축을 검사하며 위반 시 `InvalidOperationException`을 던져 `completed=false` 결함 행과 비영 종료 코드로 드러난다 — 조용한 통과 경로가 없음을 코드에서 확인했다.

### 도구 검사기와 별개의 독립 검증

도구 자체 검사기를 신뢰하지 않고 JSONL 1000행을 외부 스크립트로 재검증했다(8개 축):

- 행 수 1000 / 고유 시드 1000 / 중복 0 / 누락 0
- `completed=false` 0건, `faultType != null` 0건
- 최종 칩 음수 0건
- **칩 총량 보존**: `finalPlayerChips + finalOpponentChips == 1920` 이 1000건 전부 성립
- `roundsPlayed` 범위 이탈 0건
- 종료 원인 정합(`PlayerAllIn → 플레이어 칩 0`, `OpponentAllIn → 상대 칩 0`) 위반 0건
- 이전량 음수 0건, `amount > baseSteal`(클램프 역전) 0건
- `roundIndex` 단조 증가·범위 내 위반 0건

## 5. 카드 24(300시드) 대비 표본 안정성

시드 0..299 구간을 따로 돌린 결과가 카드 24 실측치를 **정확히 재현**했다(라운드 38.6/27.6/33.6, 승률 47.6%, 상한 패배 21.3%). 카드 24 측정과 이번 측정이 같은 파이프라인·같은 파라미터 위에 있음이 확인된다.

| 지표 | 0..299 (300건) | 300..999 (700건, 비중복) | 0..999 (1000건) | 300→1000 변화 |
|------|----------------|--------------------------|-----------------|----------------|
| 1라운드 종료 | 38.6% | 37.6% | 37.9% | -0.7pp |
| 2라운드 종료 | 27.6% | 31.4% | 30.3% | +2.7pp |
| 3라운드 종료 | 33.6% | 31.0% | 31.8% | -1.8pp |
| 승률 | 47.6% | 51.1% | 50.1% | +2.5pp |
| 상한 패배 | 21.3% | 18.0% | 19.0% | -2.3pp |
| 평균 턴 | 34.74 | — | 34.48 | -0.26 |

**판정: 표본 확대 시 안정적.** 근거는 두 가지다.

1. 모든 축의 변화폭이 n=300의 95% 신뢰구간(승률 기준 ±5.7pp) 안에 들어온다. n=1000에서 구간은 ±3.1pp로 좁혀졌다.
2. 겹치지 않는 300..999 구간(700건)을 따로 집계해도 0..299와 승률 차이가 +3.4pp로 CI 안이다. 즉 300→1000의 변화는 **표본 오차이지 구간별 체제 변화가 아니다.**

라운드 분포는 39/28/34 → 38/30/32로 소폭 평탄해졌으나 세 라운드 모두 30% 내외를 유지해 v2 튜닝 의도(1R 편중 89.5% 해소)는 표본 확대 후에도 보존된다.

> 백분율 표기 주의: 도구 콘솔은 정수 절삭(`*1000/whole`), 이 보고서의 교차 검증 스크립트는 반올림을 쓴다. 116/300이 38.6% vs 38.7%로 갈리는 것은 표기 규칙 차이이지 불일치가 아니다.

## 6. 검사기 비용

1000시드 8회 반복, 도구가 자체 계측한 배치 루프 시간(프로세스 기동 제외):

| 모드 | 중앙값 | 최소 | 관측 범위 |
|------|--------|------|-----------|
| `--check on` | 803.5 ms | 793 ms | 793~840 ms |
| `--check off` | 752.5 ms | 722 ms | 722~782 ms |

**배수 약 1.07x (중앙값 기준), 최소값끼리 비교해도 1.10x.** 1000매치 총 오버헤드가 약 51 ms, 매치당 약 0.05 ms다.

카드 24가 "대량 왕복은 off 권장"으로 기록했고 도구도 500건 이상에서 경고를 출력하지만, **실측 비용은 그 권고를 뒷받침하지 않는다**. 1000시드 전량을 `--check on`으로 돌려도 0.8초이므로 검증 배치에서 검사기를 끌 이유가 없다. 끄면 얻는 것은 50 ms인데 잃는 것은 불법 상태 검출력 전부다.

## 7. 발견 이슈

코드 수정 금지 제약에 따라 아래는 **보고만** 한다. 셋 다 이번 합격 판정을 막지 않는다.

1. **`transfers` 배열이 무승부 라운드를 생략한다 (결함 아님, 소비자 오독 위험).** 정산이 없는 라운드(`SettlementAppliedEvent` 미발생)는 항목이 추가되지 않아 `len(transfers) < roundsPlayed`가 되는 매치가 23건(2.3%) 있다. 무승부 라운드는 총 1916개 중 23개(1라운드째 10 / 2라운드째 10 / 3라운드째 3). `roundIndex`가 보존되므로 정보 손실은 없고 인덱스 단조성·범위도 전부 정상이다. 다만 JSONL 소비자가 `transfers[i]`를 i번째 라운드로 가정하면 조용히 어긋난다 — 스키마 주석에 "희소 배열, roundIndex로 접근" 명시를 권한다. (검증 중 본인도 처음에 이 가정으로 오탐을 냈다.)
2. **매치 종료 원인 6종 중 3종이 한 번도 관측되지 않는다.** `Stop` / `ExhaustedWin` / `Draw`가 1000건 전부 0이다. 이들은 라운드 종료 어휘이고 매치 종료는 올인 또는 라운드 상한으로만 나는 구조로 보이나, 매치 레벨에서 도달 가능한 값인지 확인이 필요하다. 도달 불가라면 `TerminalOrder` 출력에서 매치 레벨 어휘를 분리하는 편이 보고서 오독을 줄인다.
3. **검사기 경고 임계(500건)가 실측과 맞지 않는다.** 6절 근거로 문구 완화 또는 임계 상향을 검토할 만하다.

## 8. 결론

합격 기준 5항목 전부 통과. 1,000시드 완주 100%, 예외·불변식 위반 0건, 재실행 바이트 단위 일치, `turns` 회귀 경로 무손상. 300→1000 표본 확대에서 관측된 지표 변화는 전부 표본 오차 범위이며 v2 밸런스의 3라운드 소비 구조는 유지된다. 밸런스 조정은 이 카드의 범위가 아니므로 수행하지 않았다.
