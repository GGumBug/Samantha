# 에이전트 한국어 문체 — 번역체의 정체

에이전트가 쓴 한국어가 번역문처럼 읽히는 원인 분석. 교과서적 번역투 지표는 오히려 낮았고, 원인은 다른 네 층위에 있었다. 측정은 `tools/korean-style-audit.py`로 재현한다.

[← 저장소 루트로](../README.md) · [길이·구조 분석은 별도 보고서](agent-prose-readability.md)

---

## 요약

**번역투를 의심하고 쟀더니 번역투가 아니었다.** 피동 남용, "~에 의해", "~를 통해", "의" 연속 같은 고전적 지표는 1000자당 0.1회 미만이다. 그런데도 번역문처럼 읽힌다. 원인은 네 가지이고, 그중 첫째는 문체 문제가 아니라 **맞춤법 오류**다.

| 원인 | 실측 | 성격 |
|---|---:|---|
| 조사 앞 공백 (`Windows 에서도`) | 커밋 58.9% | 맞춤법 제41항 위반 |
| 문장 중간 줄표 | 주석 1000자당 10.3회 | 영어 구두점 이식 |
| 영어 관용구 직역 | 커밋 1000자당 7.7회 | 은유 계층의 calque |
| 한다체/합니다체 혼재 | 12개 파일 | 문체 일관성 |

첫째 항목만 고쳐도 체감은 크게 달라진다. 한국어 사용자는 `0.5 가`를 읽는 순간 사람이 쓰지 않았다고 판단한다.

---

## 1. 무엇이 원인이 **아니었나**

가설을 먼저 배제한다. 아래는 번역투 판별에 흔히 쓰이는 지표의 실측값이다.

| 지표 | 커밋 (1000자당) | 주석 (1000자당) |
|---|---:|---:|
| 피동 "되어지다 / 지게 되다" | 0.0 | 0.0 |
| "~에 의해 / 의하여" | 0.0 | 0.0 |
| "~로 인해 / 인한" | 0.0 | 0.0 |
| "~를 통해 / 통한" | 0.0 | 0.0 |
| "의" 2중 연속 | 0.0 | 0.0 |
| "~에 대한 / 대해" | 0.1 | 0.1 |
| 무생물 주어 + 타동사 | 0.2 | 0.1 |

문장도 짧다. 커밋 평균 30자, 주석 40자로 100자를 넘는 문장이 0개다. 연결어미를 3개 이상 이어붙인 문장도 2,925개 중 4개뿐이다. **구문 층위는 건강하다.** 그래서 문장을 짧게 쓰라는 처방은 이 문제에 듣지 않는다.

---

## 2. 원인 A: 조사 앞 공백 (가장 크고 가장 고치기 쉽다)

한글 맞춤법 제41항은 **"조사는 그 앞말에 붙여 쓴다"** 이다. 앞말이 로마자든 숫자든 예외가 없다.

| 대상 | 조사 앞 공백 |
|---|---:|
| 커밋 (Double-Down) | 422 / 716 (**58.9%**) |
| 커밋 (Samantha) | 118 / 300 (39.3%) |
| 규칙 문서 | 127 / 317 (40.1%) |
| C# 주석 | 540 / 4,264 (12.7%) |

실제 문장이다.

```
✗  UICardReaction 을 달고 있었고, 세 번째 SKU 만 빠져 있었다.
○  UICardReaction을 달고 있었고, 세 번째 SKU만 빠져 있었다.

✗  뷰가 0 을 넘겨도 전부 초록이다
○  뷰가 0을 넘겨도 전부 초록이다

✗  hooks-config.json 에 soundVolume 0.5 가 적혀 있는데
○  hooks-config.json에 soundVolume 0.5가 적혀 있는데
```

띄어 쓰는 이유는 짐작 가능하다. 식별자와 한글이 붙으면 식별자 경계가 흐려 보인다. 그러나 **경계를 표시하는 수단은 이미 있다**. 백틱 코드 표기다. `` `UICardReaction`을 ``이라고 쓰면 경계도 살고 맞춤법도 지킨다.

Samantha 저장소가 39.3%로 더 낮다는 점이 중요하다. 같은 사람, 같은 도구인데 저장소마다 비율이 다르다. 습관이 아니라 **주의를 준 적이 있는가**의 차이다.

## 3. 원인 B: 문장 중간 줄표

| 대상 | 문장 중간 `—` | 1000자당 |
|---|---:|---:|
| C# 주석 | 3,012 | **10.3** |
| 커밋 | 292 | 5.1 |
| 규칙 문서 | 72 | 5.1 |

2015년 시행 문장부호 규정이 드는 줄표의 용법은 **제목 다음의 부제 표시** 하나다. 문장 중간에 설명을 끼워 넣는 용법은 영어 em dash의 기능이며, 한국어는 같은 자리에 쉼표, 괄호, 또는 문장 분리를 쓴다.

```
✗  파일은 마스터로 그대로 남고 볼륨은 설정 한 줄이 된다 — 재인코딩이 필요 없다.
○  파일은 원본 그대로 두고 볼륨만 설정에서 조절한다. 재인코딩이 필요 없다.

✗  값 칸은 필수 배선이다 — 비면 무엇을 사는지 모른다.
○  값 칸은 필수 배선이다. 비면 무엇을 사는지 알 수 없다.
```

주석 한 편에 줄표가 열 번 넘게 나오면 독자는 문장의 주술 구조를 계속 재구성해야 한다. 이것이 "기계가 쓴 것 같다"는 느낌의 두 번째 축이다.

## 4. 원인 C: 영어 관용구 직역

이것이 가장 미묘하다. 이 저장소의 산문에는 일관된 은유 계층이 있다. 문제는 그 은유가 **한국어에서 나온 것이 아니라 영어 표현을 낱말 단위로 옮긴 것**이라는 점이다.

| 표현 | 빈도 (커밋/주석) | 추정 원문 |
|---|---:|---|
| 자리 | 106 / 567 | place, spot |
| 문다, 묻는다 | 69 / 53 | bites, asks |
| 운다, 우는 | 58 / 199 | fires (a warning) |
| 조용히 | 48 / 219 | silently |
| 갈린다, 가른다 | 36 / 198 | splits, diverges |
| 말한다 | 24 / 54 | says, tells |
| 얼굴 | 28 / 64 | face |
| 죽는다 | 21 / 46 | dies |
| 산다, 살고 있다 | 9 / 32 | lives in |
| 손잡이 | — | knob |
| 그물 | 8 / 4 | safety net |

합계로 커밋 1000자당 7.7회, 주석 4.8회다. 개별 표현은 저마다 그럴듯하지만 **한국어 기술 문서의 관용 어휘가 아니다.** 한국어 화자는 "테스트가 문다"나 "경고가 운다"를 읽을 때 영어 원문을 역산한다. 그 역산이 곧 번역체 감각이다.

전부 없애자는 뜻이 아니다. 판별 기준은 하나다. **한국어에서 먼저 쓰이던 비유인가, 영어를 옮긴 비유인가.**

| 유지해도 되는 것 | 바꿔야 하는 것 |
|---|---|
| 자리, 길 (한국어에 이미 있는 공간 비유) | 문다 → 검증한다, 보장한다 |
| 굽기 (Unity 도메인 용어 bake의 정착된 번역) | 운다 → 경고가 뜬다 |
| 조용히 실패한다 (업계에 정착한 표현) | 산다 → 들어 있다, 저장된다 |
| | 손잡이 → 설정 값, 옵션 |
| | 저작한다 → 직접 만든다 |
| | 그물 → 안전장치, 검증 |

```
✗  매번 우는 경고는 사람이 명부 전체를 무시하게 만든다.
○  항상 뜨는 경고는 목록 전체를 무시하게 만든다.

✗  그 그물이 실제로 무는 것을 확인했다.
○  이 테스트가 실제로 결함을 잡는지 확인했다.

✗  "이 물건이 이 물건인 이유"가 물건이 아니라 화면에 산다.
○  프리팹의 정체성이 자산이 아니라 씬에 저장된다.

✗  그 길은 설정 손잡이를 여전히 거짓말로 남겨 둔다.
○  그 방법은 설정 값이 동작하지 않는 상태를 그대로 둔다.
```

## 5. 원인 D: 한다체와 합니다체 혼재

같은 파일 안에서 두 문체가 섞인 곳이 12개다.

| 파일 | 한다체 | 합니다체 | 섞임 |
|---|---:|---:|---:|
| `.claude/agents/samantha.md` | 25 | 27 | 48.1% |
| `.claude/agents/unity-reviewer.md` | 18 | 16 | 47.1% |
| `AGENTS.md` | 44 | 39 | 47.0% |
| `.claude/agents/tars.md` | 16 | 12 | 42.9% |
| `.claude/rules/markdown-docs.md` | 8 | 12 | 40.0% |
| `CLAUDE.md` | 25 | 47 | 34.7% |
| `.claude/rules/unity-delegation.md` | 29 | 13 | 31.0% |

에이전트는 자기 정의 문서의 문체를 산출물에 그대로 옮긴다. 정의 문서가 절반씩 섞여 있으면 산출물도 섞인다. **문체 선택 자체는 취향이지만 한 문서 안에서 섞이는 것은 결함이다.**

권장: 규칙·지침·주석·커밋은 **한다체**로 통일한다. 짧고, 지시문에 적합하며, 이미 다수다. 사용자를 향한 대화 응답만 합니다체를 쓴다.

## 6. 규칙 문서만의 추가 문제: 문장 길이

구문 층위가 건강하다는 1절의 결론에 예외가 하나 있다. `.claude/rules`는 평균 51자이고 **100자를 넘는 문장이 43개**다.

```
(160자) 시니어 자가 검토는 외부 비판 압력에 비례 — 편집 직전 외부 비판자 시점
        6 질문 시뮬레이션 권장 ([best-practice/external-critique-simulation.md](...))
```

규칙 문서는 에이전트가 매번 읽는 문서다. 여기가 길면 비용이 매 세션 반복된다. 100자 초과 문장은 둘로 나눈다.

## 7. 처방

[장황함 보고서](agent-prose-readability.md) §4-3의 `.claude/rules/prose-style.md` 초안에 아래 절을 덧붙인다. 같은 Glob으로 주입되므로 파일은 하나로 유지한다(SSOT).

<details>
<summary><code>.claude/rules/prose-style.md</code> — 한국어 문체 절 초안</summary>

```markdown
## 한국어 문체 (주석·커밋·문서 공통)

### 맞춤법 — 예외 없음
- **조사는 앞말에 붙여 쓴다** (한글 맞춤법 제41항). 앞말이 로마자·숫자·기호여도 같다.
  `UICardReaction을` `0.5가` `PlayMode는`처럼 붙여 쓴다.
  식별자 경계가 필요하면 백틱을 쓴다: `` `UICardReaction`을 ``
- 줄표 `—`는 문장 중간 삽입에 쓰지 않는다. 쉼표, 괄호, 문장 분리로 대신한다.
  규정이 드는 줄표 용법은 부제 표시 하나다.

### 문체
- 주석·커밋·규칙은 **한다체**로 통일한다. 한 문서 안에서 합니다체와 섞지 않는다.
- 사용자에게 보내는 대화 응답만 합니다체를 쓴다.
- 한 문장 100자 이하. 넘으면 둘로 나눈다.

### 은유 — 영어를 옮기지 않는다
판별: 한국어에서 먼저 쓰이던 비유인가, 영어 표현을 낱말로 옮긴 것인가.
| 쓰지 않는다 | 대신 쓴다 |
|---|---|
| 테스트가 문다 | 테스트가 검증한다 / 보장한다 |
| 경고가 운다 | 경고가 뜬다 |
| 값이 화면에 산다 | 값이 씬에 저장된다 |
| 설정 손잡이 | 설정 값 / 옵션 |
| 그물 | 안전장치 / 검증 |
| 사람이 저작한다 | 사람이 직접 만든다 |
의인화된 무생물 주어도 같다. "매대가 말한다"가 아니라 "매대가 비면 ~라는 뜻이다"로 쓴다.

### 자가 검증
`python tools/korean-style-audit.py --gate`가 초록인가
```
</details>

### 적용 순서 — 비용 대비 효과 순

1. **조사 붙여쓰기**: 기계적이고 모호하지 않다. 신규 작성분에 즉시 적용하고, 기존 텍스트는 만질 때 고친다.
2. **줄표 제거**: 문장 분리로 대부분 해결된다. 주석 3,012곳은 파일을 편집할 때 함께 정리한다.
3. **문체 통일**: 에이전트 정의 5개와 `CLAUDE.md`를 한다체로 맞춘다. 이곳이 산출물 문체의 상류다.
4. **은유 교체**: 판단이 필요하므로 게이트로 강제하지 않는다. 감사 도구는 빈도만 보고한다.

## 8. 도구

```bash
python tools/korean-style-audit.py            # 커밋·주석·규칙 문서 전부
python tools/korean-style-audit.py --gate     # 임계 초과 시 exit 1
```

현재 실행 결과는 빨간불 21건이다. 임계는 스크립트 상단 상수에 모여 있어 처방과 1:1로 대응한다.

---

## 9. 미검증 항목

- **은유 계층의 가치**: 직역 은유를 걷어내면 설명이 밋밋해질 수 있다. "굽기"처럼 정착된 것과 "문다"처럼 매번 역산이 필요한 것의 경계는 사용자가 판단해야 한다. 이 보고서는 빈도만 제시한다.
- **문체 통일의 효과**: 정의 문서를 한다체로 맞추면 산출물도 따라오는지는 다음 위임 결과를 재서 확인해야 한다.
