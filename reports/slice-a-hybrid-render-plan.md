# Slice A 렌더링 아키텍처 계획 — 카드(월드 스프라이트) × 패널(uGUI) 하이브리드

2026-07-27. 「인게임 화면 구성 (확정)」 리뷰 중 나온 질문 — "패는 스프라이트인데 다른 패널들은 UI로 만드는가?" — 에 대한 기술 계획. 답은 **그렇다**이며, 기획 문구 "카드는 판에, 계기는 컬럼에"가 그대로 기술 분할선이 된다: **판(카드) = 월드 공간 SpriteRenderer, 컬럼(계기) = Screen Space uGUI.**

## 1. 현재 상태 (코드 실측)

| 항목 | 확인 결과 |
|------|-----------|
| 카드 렌더링 | `CardView` = `[RequireComponent(typeof(SpriteRenderer))]`, `sortingOrder` 직접 제어 |
| 좌표계 | `BoardLayout` 순수 함수, 직교 카메라(orthographic size 5 = 세로 10 월드 단위) 기준. `CardHeight 1.35`로 PPU 무관 정규화 |
| 입력 | `Physics2DRaycaster` + `EventSystem` (`MatchInputRig`가 코드로 보장), `CardInputTarget` 콜라이더 히트 |
| uGUI | **사용 0건** — 씬에 Canvas 없음, `UnityEngine.UI` 참조 0 |

즉 지금은 순수 월드-스프라이트 세계이고, 카드 28(플레이 UI)에서 uGUI 층이 처음 신설된다.

## 2. 분할 원칙 — 무엇이 어느 층인가

| 화면 요소 (화면 구성 문서 기준) | 층 | 근거 |
|--------------------------------|-----|------|
| 손패·바닥 월 레일·더미·획득패(중앙 5층 전부) | **월드 스프라이트** | `BoardLayout` 좌표계·입력 기구 기존 자산. 부채 회전·`scaleX` 뒤집기·비행 궤적이 transform 기반이라 자연스럽고 LitMotion과 직결 |
| 동월 부채·언더라인·카드 강조 | **월드 스프라이트** | 카드와 같은 좌표계에 있어야 착지 예측·슬롯 정렬이 어긋나지 않음 |
| 획득패 배지(광·끗·띠·피 값) | **월드 TMP** | 카드 무리 옆에 붙어 다니므로 UI 앵커 동기화(매 프레임 WorldToScreenPoint)보다 월드 텍스트가 단순 |
| 좌 컬럼(족보 게이지·칩×배수·보너스 슬롯·판돈 바) | **uGUI** | 게이지·텍스트·앵커 반응형은 uGUI 표준 영역 |
| 우 패널(문양·판돈 바·라운드·고 선언·위협순 족보) | **uGUI** | 〃 |
| 시스템 버튼·일시정지 | **uGUI** | 화면 구성 문서가 "uGUI HUD 층" 명시 |
| 대사 오버레이(카타나 제로식)·월별 잔여 팝업 | **uGUI** | 이벤트성 오버레이 — 최상단 층이 맞음 |

## 3. 층 구조와 정렬

```
직교 카메라 (orthographic size 5, 기존)
 └─ 월드 공간: SortingLayer "Cards" — 구역별 SortingBandSize(100) 밴드 (기존 유지)
Canvas (Screen Space - Overlay, 신설·카드 28)
 └─ 좌 컬럼 / 우 패널 / 시스템 버튼 / 대사·팝업 오버레이
```

- **Canvas 모드는 Overlay로 시작** — 확정 스펙상 카드가 UI 위로 겹칠 요구가 없다(획득패의 컬럼 도킹 안은 기각되고 중앙 5층으로 확정). 나중에 "카드가 게이지 위로 나는" 연출이 생기면 Screen Space - Camera + SortingLayer 편입으로 승격 — 전환 비용은 Canvas 설정 1곳.
- 컬럼/패널은 카드 영역과 **화면상 겹치지 않게** 배치되므로 두 층의 렌더 순서 충돌 자체가 없다.

## 4. 입력 공존

- **EventSystem 1개**를 양 층이 공유: `GraphicRaycaster`(uGUI, Canvas에 자동) + `Physics2DRaycaster`(카드, 기존 `MatchInputRig`).
- uGUI가 위 모듈이라 UI 요소 위 클릭은 UI가 소비 — 시스템 버튼이 카드 클릭을 가로채는 문제가 구조적으로 없음.
- **`IInputGate` 잠금 일관성**: 현재 게이트는 카드 입력만 잠근다. 카드 28에서 uGUI 버튼(고/스톱 등)도 같은 게이트를 소비하도록 배선 — 연출 중 카드만 잠기고 버튼은 눌리는 반쪽 잠금 금지.
- 키보드(카드 28.5)는 층과 무관하게 `MatchInputRouter.Submit` 단일 초크포인트 유지.

## 5. 층 경계를 넘는 연출 (정산 파이프라인)

카드 획득(월드) → 족보 게이지 팝(uGUI) 연결은 **좌표 변환 없이 이벤트로** 한다: 카드 27 표현 어댑터의 연출 큐가 "획득 카드 도착" 스텝을 완료하면 UI 게이지가 같은 큐의 다음 스텝으로 반응. 월드→스크린 좌표 변환이 필요한 연출(카드에서 게이지로 나는 파티클 등)은 Slice A 범위 외 — 폴리싱에서 `Camera.WorldToScreenPoint` 1곳으로 처리 가능.

## 6. 해상도 대응 (화면 구성 문서 미결정 항목의 기술 측 답)

- 카드 층: 직교 size 5 고정 = **세로 기준 고정, 가로는 종횡비 따라 확장** (16:9에서 가로 약 17.8).
- uGUI 층: `CanvasScaler` = Scale With Screen Size, 기준 1920×1080, **Match = 1(Height)**.
- 두 층 모두 세로 기준이므로 어떤 해상도에서도 카드와 컬럼의 상대 크기가 유지된다. 21:9 같은 초광폭은 가로 여백이 배경으로 흡수 — 컬럼을 화면 가장자리 앵커로 두면 자연 대응.

## 7. 카드별 매핑

| 카드 | 층 | 이 계획에서의 역할 |
|------|-----|-------------------|
| 27 표현 어댑터 (진행 중) | 층 무관 | 이벤트→연출 큐. 양 층이 공유하는 연출 타임라인의 소유자 — §5의 전제 |
| 27.5 레일 재설계 | 월드 | `BoardLayout` 상한 12·더미 왼쪽·동월 부채. uGUI 무관 |
| 28 플레이 UI | **uGUI 신설 본체** | Canvas·CanvasScaler·좌 컬럼·우 패널·시스템 버튼·게이트 배선. 기본 `Image`/TMP 플레이스홀더만 |
| 28.5 키보드 | 공통 | `Submit` 초크포인트 — 층 분리의 영향 없음 검증 지점 |
| 29 턴 비트 연출 | 월드 | 치기·뒤집기(`scaleX`) — 스프라이트 층 내부 완결 |

## 8. 범위 가드 (Slice A)

- uGUI 스타일링(네온·글로우·커스텀 게이지)은 **금지** — 기본 Image/TMP로 정보만. Slice A 목적은 판 길이 측정이고 카드 32가 "플레이스홀더 연출은 하한으로만 해석"을 요구한다.
- "판 중 이탈"은 **나가기 = 판 몰수(저장 없음)**로 임시 고정, 세이브 시스템은 범위 외 명시.
- 폰트는 TMP 기본(또는 기존 보유분) — 새 공유 에셋 추가 시 prefab 자동 mutation 점검 의무(unity-delegation 규칙).
