# Double Down 인게임 핸드오프

2026-09-02 갱신. 다른 PC에서 이어가기 위한 인수인계. 대상 저장소는 **Double Down** — 작업 브랜치는 **`master`**(`08f0899`까지 푸시됨). 워킹트리에 미커밋 1건: `Item_Jokbo.prefab`(레벨 배지 자리 손보기).

> **검증 루프가 코디네이터 안에서 닫힌다**: EditMode **1130** + PlayMode **68**. 사용자 왕복 없이 수정→증명 사이클이 가능하고, "이 테스트가 정말 그 버그를 잡는가"까지 **뮤테이션 1줄 토글**로 기계 증명한다 — §4.
>
> 지난 구간(MatchView 마이그레이션·택1·런 계층·상점 국면)의 커밋 서사와 당시 함정 원문은 [아카이브](double-down-handoff-archive.md)로 옮겼다. 이 문서는 현재 상태와 아직 살아 있는 함정만 든다.

| 항목 | 확정 내용 | 근거 |

| **고 보너스 정률** (2026-09-02) | 고 1회당 점 **×(1 + 20%)** 누적, 정수 내림(`go_score_bonus_bp`) | 정액이면 점수가 높을수록 고의 이득률이 떨어져 잘할수록 멈추게 된다 |
| 빈손 제시 | 손패가 비면 **묻지 않고 스톱 확정**. 좌석 무관(AI 포함) | 고는 남은 손패에 거는 베팅 — 빈손 고는 이득 0에 고박 리스크만 |
| 소진 | 스톱 없이 패가 다 떨어지면 **항상 나가리** | 실측: 소진 승자 849판 전부가 이미 제시를 받았다 |
| 나가리 배판 | 다음 판 약탈액 **×2**, 연속이면 누적 곱. 배수는 **패자 칩 상한·bet_min 하한보다 앞에서** 곱한다 | 뒤에서 곱하면 칩 총량 보존이 깨진다 |
| 상대 스톱 체감 | **룰은 바꾸지 않는다.** 연출로 해결(GDD 미정 목록 등록) | 좌석마다 다른 룰은 SSOT를 흐린다 |

### 상점·족보 업그레이드 (2026-09-02 갱신 — GDD 「런 지형 & 경제」 §4 반영)

> **어휘**: 대화·보고에서는 **족보 업그레이드**로 부른다. GDD 플레이버명 「십장생 각서」는 원문 인용 때만 병기한다. 코드·자산은 처음부터 그 결이다(`HandUpgradeCatalog`·`UpgradeOffer`·`Jokbo_Pack`).

| 항목 | 확정 내용 |
|---|---|
| 국면 | 매치 승리 → 요약 창 → 꽁지 자리 → 다음 상대. 조건은 `매치 종료 && 런 계속` 하나 |
| 세계관 | **하우스**(한국형 현대 지하 도박장). 민화·무속 조형만 폐기, 은어·십장생 매핑은 보존 |
| 그릇 | **현대 카드**. 판매는 낱장이 아니라 **팩**(뒷면 3장 겹침) |
| 팩 흐름 | 클릭 → 칩 차감 → 3장 개봉 → 1장 선택 → 나머지 소멸. **반복 레벨업**(품절 없음) |
| **업그레이드 8종** | 광 셋(3·4·5광)을 **하나로 통합**해 10종 → 8종. 족보 트래커 8줄과 1:1 |
| **기본 레벨 1** | 모든 족보가 Lv.1로 시작하고 한 번 사면 Lv.2. **모든 줄에 항상 표시**(비우는 조건 없음) |
| 솔드아웃 | **슬롯 단위** — 한 방문에서 같은 슬롯 1회, 다른 슬롯은 영향 없음. 해제는 세션 수명(다음 방문 자동) |
| 가격 | 시트 `pack_price`(현재 100 — 자리채움). 수치 확정은 **chip_total 상향과 한 세트 재측정** |

**광을 통합한 이유는 단순화가 아니라 결함 제거다.** 광 셋은 같은 조건(`ForCategory(Gwang)`)에 문턱만 다르고 `exclusive_group` 이라 **한 판에 하나만 점수가 된다**. 별도 상품이면 3광에 Lv.5 를 투자한 사람이 광 5장을 모으는 순간 그 투자가 0점이 됐다 — **잘하면 손해 보는 구조**였고, 투자 대상과 실현 대상이 갈리는 것이 원인이라 수치로는 못 고친다.

**밸런스 주의 (재측정 시 볼 것)**: 통합 광은 **적중률**이 다른 업그레이드보다 높다(한 번 사면 세 문턱에 다 붙는다). 대신 **점수 체감은 낮다**. 두 힘이 상쇄되는지는 측정 전에 알 수 없으므로 **광 선택 빈도**와 **광 빌드 승률**을 별도 지표로 볼 것.

### 왜 문턱 스케일링을 버렸나 (2026-09-02 — 되살리지 말 것)

문턱을 덱 강화 가중으로 올리면 **잠재 강화량**을 상쇄하는데, 정작 문턱이 비교하는 값은 **실현 점수**다. 가중은 산 강화 전부를 더하지만 기본 점수는 그 판에 실제로 성립한 족보에서만 오른다 — 세트형을 두 번 사면 문턱이 11이 되고, 그 판에 광이 안 나오면 점수는 1점도 따라오지 않는다.

**제시가 없으면 스톱도 없다.** `DeclareStop` 은 `AwaitingGoStop` 에서만 합법이고 그 상태는 제시 판정으로만 들어간다. 문턱이 도달 불가가 된 순간 플레이어는 라운드를 끝낼 수단을 잃고 매 판이 나가리로 끝난다. 상대 덱은 비어 있어 문턱이 7 그대로라, **강화를 살수록 나만 못 이기고 상대만 이길 수 있는** 상태가 됐다.

원래 걱정("강화로 점수가 인플레되면 문턱이 무의미해진다")은 **옳았다** — 틀린 것은 상쇄 대상이었다. 난이도는 **상대 칩 총량 × 3라운드 상한**이 담당한다(8월 실측: 라운드 상한 패배 21.3%). 문턱이 같은 일을 두 번 할 이유가 없다. 폐기 사유는 `GoStopJudge` 클래스 doc 에도 박아 뒀다.

## 2. ⚠️ 새 PC에서 첫 3분

1. **양쪽 저장소 pull** — 둘 다 `master`
2. **Unity 열고 컴파일 확인** — 에러 0건
3. **`tools/ddtest.sh` 경로 3줄 수정** — `SRC`·`DST`·`UNITY`. 그러면 EditMode 전량이 십수 초에 돈다(§4). 이 스크립트는 **git 에 없다**(머신 로컬) — 없으면 §4 의 배치 명령 원형을 직접 쓴다
4. **도구 두 개가 사는지 확인** — `dotnet build Double-Down.slnx`(오류 0) 와 `cd Tools/HeadlessSim && dotnet run -c Release --project . -- 200`. **후자는 Unity 컴파일 단위 밖이라 아무도 안 지켜본다** — 실제로 15일간 죽어 있었다(§5). 첫 3분에 넣는 이유가 그것이다
5. **재생 검증 5종** — 다음 판 더미·상대 손패 전부 뒷면 / 쪽·따닥·싹쓸이·뻑해소의 피 약탈 / 카드가 UI 패널에 안 물림 / 마지막 패의 치기→상대 턴→종료 순서 / 모든 패가 바닥 경유
6. **택1 확인** — 후보가 창 중앙 가로 행으로 펼쳐지고, 확대 위 호버가 먹고, 그림자가 따라오고, 고르면 왔던 길로 내려간다
7. **상점 확인** — 디버그 모드(§4)로 선수전 승리 → 매대에 팩 → 구매 → 3장 개봉 → 선택 → 팩 자리 품절 → LEAVE
8. **업그레이드 반영 확인** — 트래커의 해당 줄이 **Lv.2**, 점수 칸이 오른 값
9. **고/스톱이 강화에 안 막히는지** — 메뉴 `Double Down/Debug Mode` 켜고 **강화 부여**로 세트형(광 등) 2회 → `이 선수 승리` → 다음 판 진입 → **계기판 점수 칸 오른쪽(필요 점수)이 7 이면 통과.** 여기가 9·11 로 올라가 있으면 문턱 스케일링이 되살아난 것이다(§1)

## 3. 지금 하던 일 — 성장 시스템 (상점 → 업그레이드 → 적용)

**2026-09-02 마감 시점**: **한 바퀴가 닫혔다.** 사면 다음 판이 실제로 세진다 — 상점에서 팩을 사고, 셋 중 하나를 고르고, 그 레벨이 채점에 반영되고, 트래커가 오른 점수와 그 레벨을 함께 그린다. 전 층이 초록이다.

계층은 도메인(`HandUpgradeCatalog` 8행·`RunUpgrades`·`RunFlow.TrySpendChips`) → 응용(`ShopSession`·`UpgradeOffer`·`ScoreLineProgressCatalog.ForUpgrades`) → 화면(`ShopView` 매대·개봉 3택1, `JokboTrackerLine` 점수·배지)이다.

**문턱은 강화와 무관하다** — 스케일링을 폐기했다(§1). 강화가 아무리 쌓여도 제시 시점은 강화 0 런과 같고, 그 불변식은 뮤테이션으로 동결돼 있다(`GoStopTests` 시나리오 9).

**⚠️ 수치는 전부 자리채움이다** — 레벨당 점수(세트 2 / 수집 1)도 `pack_price`(100)도 밸런스 문서가 "미확정"이라 적어 둔 값이다. 이제 적용 경로가 서서 **잴 수 있다**.

### 다음 후보

- **⭐ 수치 재측정 (진행 중)** — 측정 하네스는 **HeadlessSim** 이다(§4). Unity 스윕(`RunLadderSweepScratch`)은 `[Explicit]` + 이 환경의 `-testFilter` 고장 조합이라 돌릴 수 없다. 재는 것: ⓐ 라운드 상한 패배율(기준선 **21.3%**) ⓑ 라운드당 제시 횟수 ⓒ 고 횟수 분포 ⓓ 첫 제시 턴. **시뮬은 런 덱을 모델링하지 않아 강화 0** 이고, 강화 0 에서는 문턱 변경이 무영향이라 **정률화의 순효과만 분리해 잰다**
- **고배수 편향 (측정 후 결정)** — 고배수는 `3고 ×2 · 4고 ×4 · 5고 ×8` 로 **고 선언 횟수**의 함수인데, 그 횟수는 점수가 몇 조각으로 나뉘어 들어왔는지에 달렸다. 수집형은 매 턴 +1 이라 기회가 많고 **세트형은 완성 전까지 0점이라 문턱을 늦게 넘어 기회가 적다** — 최대 곱셈 축에서 빌드 타입이 갈린다. 완만화(지수→선형)는 **식 변경이라 시트 값으로 안 된다**. ③ 의 ⓒ·ⓓ 를 보고 결정
- **수집형 구매 가치의 성격 차이** — 수집형은 문턱을 딱 채운 판에서 강화가 완전히 무효다(초과 0장이면 delta 가 0 에 곱해진다). 세트형과 근본적으로 다르므로 두 타입에 같은 가격을 매기면 수집형이 구조적 함정이 된다
- **개명 카드** — `UpgradeOffer.Level`·`ScoreLineStage.UpgradeLevel`·`RunUpgrades.LevelOf` 가 이제 전부 **구매 횟수**를 뜻한다(표시만 +1). doc 으로 뜻을 고정해 뒀지만 이름은 여전히 "레벨"이라, `PurchaseCount` 계열로 옮기면 정직해진다. 저장·상점·표시 3계층 + 테스트 관통이라 파급이 크다
- **상점 미끄럼 연출** — 사용자 설계: 화면이 위에서 내려와 멈춘다(`Image_BG` 가 패널만 덮는 이유). `Open`/`Close` 동기 계약을 바꾸므로 **전용 카드** — 생명주기 테스트 9건 재계약 + LitMotion 룰 7
- **G1 잔여: 보너스 피 장착 축** — `CreateFlow` 의 `Empty` 4자리는 여전히 비어 있다(족보 업그레이드는 그 슬롯이 아니라 점수표 축). 효과 엔진(까치호랑이·개평꾼)은 완성돼 대기 중
- **리롤 / 보너스 피 매대 / 소모품 / 사채** — 시트에 `loan_limit`·`loan_interest_bp` 가 이미 있고 미배선. 매대 슬롯 확장 시 `ShopSlotView` 부품화 논의 있었음(사용자 제안 — 슬롯 3~4개 확정이라 두 번째 슬롯부터 값)
- **런 종료 화면 / 막 표시 데이터화 / `special_steal_pi_count` 배선 / `pi_bak_loser_max < pi_bak_winner_min` 확인** — 이전 목록 유지
- **연출 다듬기 소묶음** — 죽은 손잡이(`TurnBeatBudget._choiceLiftFactor`) 제거 · 그림자 각도 테스트 공백 · 택1/선언 수치 조정 · `FloorChoicePopupView` 개명(주소 동반) · 턴 전환 연출 · `SetFastBattle` 노출

## 4. 검증 도구

배치 실행 스크립트는 **[`tools/ddtest.sh`](../tools/ddtest.sh)** 로 저장소에 있다. 경로 상수(`SRC`·`DST`·`UNITY`) 세 줄만 PC에 맞춘다. 함정 목록은 스크립트 주석에도 박혀 있다.

### ⭐ Unity 배치 모드 실행 (주 도구)

**EditMode 전량(1130건)이 십수 초.** Personal 라이선스로 동작, `unity` CLI 불필요.

```bash
bash tools/ddtest.sh                    # 전량
bash tools/ddtest.sh --full-sync        # 사본 재생성 (패키지 캐시 어긋났을 때, 수 분)
```

**PlayMode 68건은 스크립트가 돌리지 않는다** — 같은 사본에 `-testPlatform PlayMode` 로 직접.

**⭐ `NUnit could not be found` 는 코드 오류가 아니다** — 사본 패키지 캐시가 어긋난 것. `--full-sync` 한 번이면 끝난다.

**재작성 시 다섯 함정** (전부 실제로 밟았다): ① `-quit` 금지(임포트 직후 종료돼도 종료 코드 0) ② 사본에서 돌린다(원본은 에디터가 잠금) ③ `Library` 는 동기화 제외(임포트 캐시가 자산) ④ `MSYS_NO_PATHCONV=1` 필수 ⑤ 출력 인코딩 UTF-8 고정.

**라이선스 첫 에러(`Code 10 …`)에서 읽기를 멈추지 말 것** — 재연결 후 성공 로그가 뒤에 있다.

**macOS**: 사본 없이 원본 직접 실행 가능(에디터 반드시 닫기). 결과 판정은 XML 루트 속성 — **`skipped` 를 반드시 함께 본다**(`Assert.Ignore` 는 `failed=0` 이라 총계만 보면 통과로 읽힌다).

**`-testFilter` 는 이 환경에서 빈 값으로 전달된다**(`Scan Filter Count: 0` → 무실행). **전량 실행 + 총계 대조**로 간다 — 새 테스트 N개면 총계가 정확히 +N 이어야 한다. 완료 판정은 프로세스 종료가 아니라 **XML 존재**로.

**행 판정 3지표**: CPU ~0% + 로그 크기 정지 + 완주본 크기 미달. 처방은 `pkill` 후 `Temp/UnityLockfile` 제거.

### ⭐ 에디터를 닫지 않고 컴파일 검증 (2026-09-02 발견)

```bash
dotnet build Double-Down.slnx
```

Unity 생성 `.csproj` 로 전 어셈블리를 컴파일한다 — **에디터가 열려 있어도 된다.** 대규모 편집 뒤 가장 큰 위험(컴파일 불가)이 에디터 락과 무관하게 제거되므로, 사용자에게 "Unity 닫아 주세요"를 요청하기 **전에** 이걸 먼저 돌린다. 기준: 오류 0 · 경고 9(전부 기존 — `[SerializeField]` CS0649 와 Easy Save 3 플러그인).

단, **컴파일 통과는 테스트 통과가 아니다.** 값·개명이 얽힌 변경은 배치 실행까지 가야 한다.

### ⭐ HeadlessSim — Unity 밖 도메인 실행


`Domain/**` · `Simulation/**` · `Application/**` 소스를 순수 .NET 콘솔로 컴파일한다(csproj `Compile Include`). **에디터 락도 `[Explicit]` 도 깨진 `-testFilter` 도 없다.** 밸런스 측정의 정본 경로다.

### 뮤테이션 검증 — "이 테스트가 정말 그 버그를 잡는가"

초록불만으로는 "통과한다"와 "무언가를 검증한다"가 구별되지 않는다. 고친 그 변이 하나에 수동 뮤테이션:

1. 수정 상태로 실행 → 전부 초록
2. 버그를 정확히 한 줄 되돌림 → **예상한 케이스만** 빨간불인지 확인 (넓게 번지면 테스트들이 서로 침범 중)
3. 즉시 복원

**⭐ 절차 게이트 — "확인하라"가 아니라 "커밋 먼저" (2026-09-02 강화)**: `git checkout` 원복으로 미커밋 작업을 날린 사고가 **세 번** 났다. 세 번째는 룰을 쓴 당일에 났다 — 문구는 정확했는데 **"확인하라"가 판단 요구라 지친 구간에서 건너뛰어진다**.

> **미커밋 파일에는 뮤테이션을 걸지 않는다. 걸어야 하면 먼저 커밋한다.**
> `git checkout` 원복은 **그 파일이 커밋 상태일 때만** 쓴다.

커밋이 확인보다 나은 이유는 그 자체가 안전망이기 때문이다 — 확인은 잊을 수 있지만 커밋된 것은 잃을 수 없다. 실제로 카드 C·E 후반부는 커밋 먼저 하고 뮤테이션해 사고가 없었다. [evaluation.md](../.claude/rules/evaluation.md) 가 정본이다.

### 시뮬레이션 프로브

`MatchFlow` + `HeuristicAiPolicy` 로 수천 판을 돌리며 이벤트 스트림에서 불변식 전수 검사. `IEventSink` 구현 하나 + `Pcg32RandomFactory`. 실적: 마지막 패 역전 분포 실측 · 특수상황 미배선 발견 · 약탈 존 이동 불변식 4,294건 위반 0. 큰 리팩토링의 회귀 판정은 **전 커밋을 워크트리로 꺼내 같은 시드를 양쪽에서 돌려 분포 대조**(시드별 일치가 아니라 — 난수 소비가 달라지면 시드별 결과는 정당하게 갈린다).

### ⭐ 디버그 모드 — 사다리를 초 단위로

메뉴 **`Double Down/Debug Mode`** 로 켠다(체크마크로 상태가 보인다). 켜면 `OnGUI` 에 문 다섯: 이 라운드 승리/패배(매치 계속) · **이 선수 승리/패배**(요약 창 → 상점 → 다음 상대) · **강화 부여**(각서 8종 `+1`).

- **라운드 버튼만으로는 상점에 못 간다** — 강제 스톱은 이전량이 `bet_min` 으로 깔려 한도 소진 패배가 된다. 그래서 선수전 버튼이 따로 있다.
- **안전 원칙 — 합성하는 것은 트리거뿐.** 정산·칩 이전·terminal 판정·런 소비는 전부 실경로가 한다. 강화 부여도 본문이 `RunUpgrades.Raise` 한 줄이라 **N 번 부른 상태 = N 번 산 상태**다. 이중 정산은 `LootSettler` 의 패자 칩 상한이 **마지막에** 걸려 스스로 0이 된다 — 프로덕션에 디버그 분기가 0줄인 근거.
- **강화 부여는 다음 판이 설 때 반영된다** — 트래커·채점이 읽는 값이 판 스코프에서 동결되기 때문. 갱신을 강제하지 **않은** 것이 의도다: 도구가 그 계약을 우회하면 도구로 본 화면이 게임의 화면과 갈린다.
- **칩 부여 문은 없다** — `RunFlow` 에 칩을 넣는 공개 API 가 없고(`TrySpendChips` 는 빼기만) 칩은 이미 "이 선수 승리" 문이 정산 실경로로 준다. 같은 일을 하는 문을 둘로 만들지 않는다.
- **스위치는 씬이 아니라 `EditorPrefs` 에 산다**(2026-09-03) — 씬에 두었을 때 `_debugMode: 1` 이 **네 번** 커밋됐다. 이제 커밋될 경로 자체가 없고, `#if UNITY_EDITOR` 라 출고 빌드에 컴파일되지도 않는다.

### 값 흐름 프로브 — "배선이 실제로 열렸는가"

계약·DI·테스트가 초록이어도 화면은 옛 기본값을 볼 수 있다. 판정법은 **두 경로가 다른 값을 내는 지점 하나**를 고르는 것(시트 450 vs Placeholder 720 — 화면 한 번에 갈린다). 값이 같은 지점은 아무것도 말하지 못한다.

## 5. 함정 (이미 밟은 것 — 반복 금지)

### 2026-09-03 (문턱 폐기·정률 전환·도구 정비)

- **⭐ 필수 인자 규율에는 컴파일 단위 사각지대가 있다** — 새 축을 필수 인자로 넣으면 "컴파일러가 생산 지점 명부를 만든다"가 성립하지만, 그 명부는 **컴파일되는 범위 안에서만** 만들어진다. `MatchBalance` 가 배판 인자를 받게 된 날 `Assets/` 생산 지점은 전부 잡혔고 `Tools/HeadlessSim` 만 빠져 **15일간 빌드 불가**였다. 저장소에 컴파일 단위가 둘이면 이 규율은 한쪽에서만 선다. 처방: 도구도 주기적으로 빌드하거나(§4 첫 3분에 추가) 같은 솔루션에 묶을 것
- **⭐ 스위치를 자산 파일에 두면 켜는 행위가 곧 커밋이다** — `_debugMode` 가 `[SerializeField]` 라 `_debugMode: 1` 이 **네 번** 커밋됐다. Unity 는 재생 중 만진 값도 씬에 적어 넣어 "켜고 저장 안 하기"가 성립하지 않는다. `EditorPrefs` 로 옮기니 커밋될 경로 자체가 사라졌고, `#if UNITY_EDITOR` 를 겸해 도구가 출고 빌드에 **물리적으로** 못 들어간다. 사람의 기억에 기대는 안전장치를 구조로 바꾼 자리
- **⭐ 테스트 총계 대조로는 개명이 안 보인다** — 총계 −2 인데 실제로는 **4 건이 사라지고 2 건이 생긴** 것이었다(삭제 2 + 개명 2). 또 다른 날은 `[Test]` 7 건을 지웠는데 총계가 9 줄었다 — 배열 항목 하나가 파라미터화 테스트 둘에 케이스를 공급하고 있었다. **두 XML 의 테스트 이름 집합을 직접 빼라**(§4)
- **뮤테이션이 0 을 잡으면 안전이 아니라 눈이 없다는 뜻** — 표시 계층에 검증이 없어 수집형 강화 버그를 심어도 죽는 테스트가 0 건이었다(테스트를 붙인 뒤 같은 뮤테이션에 8 건)
- **단위가 바뀌면 "주입값이 관측 가능한가"를 전수하라** — 밸런스 주입 소비를 증명하던 케이스의 주입값 `2` 가 정액에서는 +4점이었지만 만분율에서는 0.02% 라 내림에 먹혔다. 기대값만 낮추면 **무엇을 넣어도 통과하는** 공허한 단언이 된다. 같은 파일에 같은 성질이 한 자리 더 있었다
- **골든의 기대값이 커지면 상한이 새로 걸릴 수 있다** — 보정 점수가 오르자 약탈액이 패자 재산을 넘어 클램프가 발동했고, 그대로 두면 종단값이 "패자 전 재산"으로 굳어 *어느 축 회귀도 감지한다*는 계약이 죽는다. 픽스처 입력을 올려 클램프 미발동을 보존했다(상한 자체는 전용 케이스 다섯이 따로 덮는다)
- **위임은 편집만 시키고 검증은 코디네이터가** — 세 에이전트가 연속으로 **검증 단계에서** 25턴 절단됐다. Unity 배치 실행 + XML 파싱이 8~10턴을 먹는다. 편집/검증을 가르니 절단이 멎었다

### 2026-09-02 (채점 주입·광 통합·기본 레벨 1)

- **⭐ 표시 계층에 검증이 없으면 뮤테이션이 0을 잡는다** — 수집형 강화는 `PerExtraScore` 에 붙는데 트래커는 `BaseScore` 만 그렸다. 화면에서 안 보이는 버그였고, **버그를 심어도 죽는 테스트가 0건**이었다(테스트를 붙인 뒤 같은 뮤테이션에 8건). 뮤테이션이 0을 잡으면 그건 "안전"이 아니라 **그 계층에 눈이 없다는 뜻**이다.
- **⭐ 키가 `string` 이면 컴파일러가 개명을 안 막는다** — 광 통합으로 `HandUpgradeLevels` 의 키가 족보 id 에서 업그레이드 id 로 바뀌었다. 타입은 똑같은 `string` 이라 잘못 넘겨도 조용히 레벨 0 이다. 방어는 **경유 함수 하나**(`ForHand`)로 좁히고 카탈로그 불변식(10 족보를 정확히 한 번씩 덮는다)을 테스트로 세운 것.
- **⭐ 배타 그룹을 공유하는 족보를 따로 강화하면 "잘하면 손해"가 된다** — 3광에 투자한 뒤 5광에 닿는 순간 그 투자가 통째로 죽는다. 숫자로 못 고치는 **설계 결함**이라 8종 통합으로 갔다. 배타·포함 관계가 있는 대상에 개별 성장을 붙일 때마다 이 질문을 할 것.
- **저장이 뜻하는 바와 표시가 뜻하는 바를 가르고, `+1` 은 한 곳에서만** — 기본 레벨 1은 표시 규약이고 저장은 여전히 구매 횟수다(점수식이 그것을 쓴다). `FormatUpgradeLevel` 한 함수에서만 더한다. 대가로 `Level` 이라는 이름들이 이제 구매 횟수를 뜻해 doc 으로 고정해 뒀다 — 개명 카드는 §3.
- **⭐ 세 번째 `git checkout` 사고 — 룰이 "확인하라"면 지친 구간에서 건너뛰어진다** — `HandUpgradeCatalog.cs` 의 통합 작업 전부를 날렸다(복원 완료). 룰을 쓴 당일이었다. 문구를 **"커밋 먼저"** 라는 기계적 순서로 바꿨다 → §4.
- **5개 넘는 파일을 한 위임에 몰면 탐색만 하다 25턴에 끊긴다** — 편집 0건으로 절단됐다(저장소 자신의 룰을 내가 어겼다). Part A/B 로 갈라 둘 다 완주.

### 2026-09-01 (상점 팩·족보 업그레이드)

- **⭐ 완전성을 주장하는 감사가 검사 목록을 손으로 들면, 새 축이 온 날 감사 자신이 조용히 거짓이 된다** — `Shop` 축이 로더 감사에서 그렇게 빠졌고, 같은 병이 한 파일에 두 자리 더 있었다. 처방(목록을 검사 대상에서 파생 + 뮤테이션 증명)은 [hand-listed-roster-decay](../best-practice/hand-listed-roster-decay.md) 로 승격.
- **⭐ 표현 계층이 부를 API 는 반환 타입의 어셈블리를 먼저 본다** — `BuyPackAndDraw` 가 Domain 타입을 반환해 UI 가 못 불렀다. asmdef 는 컴파일러가 강제하는 계층 경계이고, 경계를 넘는 선례(`ScoreLineKind`→`HudWords`)가 저장소에 이미 있었다. [assembly-boundary-api-design](../best-practice/assembly-boundary-api-design.md) 로 승격.
- **픽셀 폰트에 없는 글리프는 폰트를 다시 굽지 말고 이미지로** — `▸`(U+25B8)가 깨졌는데, 족보 트래커가 **이미 `Image_Arrow` 로 해결**해 뒀었다(doc 의 "1 ▸ 3"은 표기일 뿐 화면은 이미지). 공유 폰트 재생성은 파급이 화면 밖으로 나간다 — 이 저장소는 폰트 추가로 의도 외 프리팹 GUID 교체를 겪었다(2026-05-14). **같은 증상을 저장소가 이미 해결했는지부터 grep.**
- **인스턴스가 하나라도 확정 설계가 N개면 상태·이름을 슬롯 단위로** — 솔드아웃을 `_purchased`(전역)로 지었다면 두 번째 매대가 오는 날 의미가 갈렸다. 사용자 정정("그 아이템만 비워지는 것")으로 `_packSoldOut` 이 됐다.
- **한 파일에 미커밋 작업이 몇 겹인지 뮤테이션 전에 세라** — `ShopSession.cs` 에 두 카드 분량이 쌓인 채 `git checkout` 원복을 해 전부 날렸다(복원 완료). 절차 게이트는 §4 뮤테이션 절 참조.
- **주석의 근거가 자산과 갈릴 수 있다** — `ShopView` doc 이 "`Image_BG` 가 화면을 덮는다"를 `SetActive` 근거로 댔는데 실측은 패널만 덮었다(미끄럼 연출 전제라 그게 의도). 결론이 옳아도 **거짓 근거는 다음 사람을 틀린 길로 보낸다** — 실측과 갈린 주석은 발견 즉시 정정.

### 2026-08-31 (상점 국면·디버그 문·이음매·런 계층)

- **⭐ 파생 규칙이 상태를 안 보면 상태가 하나 늘 때 조용히 틀린다**: 라운드 칸 `+1` 규칙이 두 상태에서 옳아서, 세 번째(`Ended`)가 생겼을 때 아무도 다시 세지 않았다(`4 | 3` 표시).
- **⭐ 증상을 지우는 수정이 원인을 반만 고친다**: 위 버그를 clamp 로 고치면 3라운드 승리는 맞아지지만 2라운드 파산승이 이긴 적 없는 라운드를 그린다 — 증상이 없어 아무도 모른다. 동결 케이스를 둘로 나눴고 뮤테이션에서 **두 번째만** 죽는 것을 확인했다.
- **⭐ 도구가 만드는 상태는 게임이 만들 수 있는 상태여야 한다**: 개발 짐 설계가 세 번 뒤집히는 동안 매번 살아남은 제약. 최종 형태는 **트리거만 합성**하고 나머지는 실경로.
- **막는 장치를 만들기 전에 이미 있는 규칙이 막는지 보라**: 이중 정산 방지 코드를 안 만들었다 — `LootSettler` 상한이 마지막에 걸린다는 실측이 근거다. 순서가 반대였다면 깨졌다 — 추측으로 걸 수 없어 범위를 넘어 읽은 판단이 옳았다.
- **`git add` 전에 `git diff --cached --stat` 을 눈으로 읽을 것**: 에이전트가 스테이징해 둔 삭제 4건이 다른 커밋에 함께 나갔다(`f32f912`).
- **⭐ 두 계층이 각자 옳은데 이어졌을 때 갈릴 수 있다**: 창 테스트와 공장 테스트가 각자 초록인데 "창이 적은 그 순간 다음 발급이 정말 그것인지"는 아무도 안 봤다. 처방은 이음매 테스트 — 기대값을 상수가 아니라 **창이 적은 문구에서 파생**.
- **런 전진이 화면 확인보다 먼저인 것은 수명이 떠받친다**: 공장이 씬 컨테이너 싱글톤이라 무해하다. **저장·이어하기로 런을 루트 스코프에 올리면 상대 하나를 건너뛴다** — 근거를 `MatchSceneInstaller` 에 적어 뒀다.
- **시드 탐색 테스트는 밸런스 변경에 먼저 빨개진다**: 못 찾으면 `Inconclusive` 가 아니라 **실패**다. 밸런스를 크게 바꾸면 `RunExitSeamTests`·`ShopFactoryWiringTests` 가 먼저 터질 수 있다 — 회귀가 아니라 **도달 불가 신호**로 읽을 것.
- **⭐ 조각이 다 초록인데 이은 자리가 비어 있었다**: 907건 초록인데 게임은 첫 패배에서 멈췄다. 계층을 잇는 위임마다 **한 바퀴 도는 통합 테스트를 같은 단계에서** 요구할 것.
- **⭐ 시끄러운 실패를 조용한 실패로 바꾸지 말 것**: 존재하지 않는 막 번호를 고쳤더니 유효 좌표가 되어 "이미 이긴 상대"를 조용히 되돌려주게 됐다. 답은 값이 아니라 **축을 타입으로 가르는 것**(`Act`/`SlotIndex` 표시용 vs `NextAct`/`NextGrade` 국면 가드).
- **⭐ 에이전트가 뮤테이션을 넣은 채 25턴에 절단될 수 있다**: 위임 프롬프트에 "남은 턴이 빠듯하면 뮤테이션 시작 금지" + `// MUTATION` 마커 + 절단 후 구현 파일 grep 게이트.
- **⭐ 테스트 모드는 폴더의 asmdef 가 이미 정해 놓았다**: `includePlatforms` 를 먼저 보고, 실행 후 **총계 증가분**을 확인할 것 — 새 테스트가 안 돌아도 총계만 보면 정상으로 읽힌다.

### 2026-08-30~31 (데이터·밸런스)

- **⭐ 만들라는 것이 이미 있는지 먼저 열어 볼 것**: "3라운드 매치 규칙"은 도메인에 전부 있었고 골든 케이스로 동결까지 돼 있었다. 이 저장소는 규칙이 코드에 먼저 서고 화면이 늦게 따라온다 — 규칙 요청은 `Domain/` 부터 연다.
- **⭐ 축을 더할 때는 생산 지점만이 아니라 검증 지점도 전수**: 값을 만드는 곳과 값을 동결하는 곳은 다른 명부다. → 이 병의 일반형이 [hand-listed-roster-decay](../best-practice/hand-listed-roster-decay.md)
- **⭐ 함께 들어오는 값은 함께 나가야 한다**: 진입점을 한 인자로 묶으면 들어오는 쪽은 컴파일러가 막지만 **나가는 쪽(`ResetForNewMatch`)은 아무도 안 막는다**.
- **⭐ 데이터 행을 켜는 것과 기능을 켜는 것은 다르다**: 2·3막 행을 켜자 `FinalAct` 가 조용히 3이 됐다. **2막을 켜는 날 `FinalAct` 를 읽는 자리를 전부 확인할 것.**
- **시트에서 컬럼 구조를 바꾸면 BGDatabase 가 되돌린다** / **행은 시트가 이긴다** — 구조(컬럼)와 데이터(행)는 다른 축.
- **생성 타입(`Db*`)은 어댑터 밖으로 내보내지 말 것**: 세터가 살아 있고, 런타임 변경은 다음 임포트에 조용히 되돌아간다.
- **주석이 제거한 타입명을 되살려 grep 게이트를 깨뜨릴 수 있다**: 제거 게이트를 grep 으로 세울 때는 주석도 대상이다.
- **`Placeholder` 를 지우지 않고 의미를 바꿨다**: 프로덕션 사용처 0건(grep 게이트) + **시트값과 갈라지면 빨간불 테스트**. 안 두면 둘 다 초록인 채 다른 밸런스로 돈다.

### 이전 세션 (여전히 유효)

- **선택 인자가 미배선을 숨긴다**: 새 축·판정기는 **필수 인자**로 — 컴파일러가 생산 지점 명부를 만든다.
- **`.csproj` 거짓 녹색**: 신규 `.cs` 는 재임포트 전까지 컴파일 대상이 아니면서 0 오류로 통과한다.
- **시간축 버그는 밀리초를 찍기 전에는 갈리지 않는다** (겹침 vs 간격 0).
- **없는 로그를 "그런 일이 없었다"로 읽지 말 것.**
- **초록불이 검증을 뜻하지 않는다**: 설정값을 끄면 그 값을 재던 테스트가 공허하게 통과한다.
- **설정 기본값을 동결하는 테스트는 소리 없이 낡는다**: `CreateInstance<T>()` 는 `.asset` 이 아니라 C# 기본값을 잰다.
- **넓은 가드를 좁힐 때는 그 가드가 막던 실제 문제를 먼저 찾는다** — 가드에 이유가 주석으로 적혀 있어 발견했다.
- **생명주기 승격**: `MatchView`·`GoStopView` 는 DDOL — 재시작 잔재 0은 파괴가 아니라 상태 초기화로.
- **첫 진입 순서**: 씬은 판을 먼저, UI 를 나중에 세운다 — `_view?.Bind(...)` 널 가드는 첫 판에서 조용히 지나가므로 `PrepareUiAsync` 보정 밀기를 함께 걸 것.
- **라운드 스코프 상태의 실제 수명**: "라운드 스코프" 주석이 실제로 `Clear()` 되는지 확인. 공개 맵은 획득 카드 원형 복원에 살아 있다 — 지우면 획득 집계가 조용히 0.
- **`ReleaseAll` 금지**: 전 뷰 파기라 로딩 커튼까지 죽인다. 씬 이탈은 `Close<T>()`.
- **stale `.csproj`**: asmdef 수정 후 재임포트 전까지 옛 참조 — CS0234 는 코드보다 이걸 의심.
- 2026-08-29 구간(택1·턴 재구성)의 함정 원문은 [아카이브](double-down-handoff-archive.md) — 요지: 경유 경로 검증 / 두 의미 필드 분리 / 수명이 다른 상태를 같은 해제 지점에 묶지 않기 / `transform.Find` 는 직속 자식만.
