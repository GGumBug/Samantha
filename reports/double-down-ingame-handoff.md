# Double Down 인게임 핸드오프

2026-08-19 갱신. 다른 PC에서 이어가기 위한 인수인계. 대상 저장소는 **Double Down**, 기준 브랜치는 **`master`**(`646826f`까지 푸시 완료).

> **브랜치 변경**: `feature/ui`는 전량 `master`에 병합됐다. 이제 `master`에서 작업한다.
>
> MatchView `IUIService` 마이그레이션과 계기판 배선은 **완료**되어 이 문서의 주제가 아니다(§7 이력). 살아 있는 작업은 §3이다.

## 1. 확정 결정 (재논의 금지)

### UI 구조

| 결정 | 내용 |
|------|------|
| UIManager 실체 | GameCore의 `IUIService`/`UIService`. **새 관리자 클래스 신설 금지**(SSOT 위반) |
| UI 로드 경로 | Addressables, 주소 = `typeof(T).Name` |
| 화면 스펙 SSOT | Notion 「인게임 화면 구성 (확정)」 — **유추 금지, 원문을 먼저 연다**(헌법 §0-1) |

### 룰 (이번 세션에서 확정 — GDD §2-1-1에 반영됨)

| 항목 | 확정 내용 | 근거 |
|---|---|---|
| 고/스톱 제시 | **문턱 점수 하나**(기준선 7점) + 재선언 가드. 복수 라인·상대 우세는 **후반 조건부 페널티로 이월** | 초반에 강화가 없어 방어할 인플레도 없었다 |
| 빈손 제시 | 손패가 비면 **묻지 않고 스톱 확정**. 좌석 무관(AI 포함) | 고는 남은 손패에 거는 베팅 — 빈손 고는 이득 0에 고박 리스크만 |
| 소진 | 스톱 없이 패가 다 떨어지면 **항상 나가리** | 시뮬레이션 실측: 소진 승자 849판 **전부**가 이미 제시를 받았고 75%는 마지막 턴에도 받고 고를 택했다 — "물어보지도 못하고 끝나는" 판은 없었다 |
| 나가리 배판 | 다음 판 약탈액 **×2**, 연속이면 누적 곱. 배수는 **패자 칩 상한·bet_min 하한보다 앞에서** 곱한다 | 뒤에서 곱하면 가진 것보다 많이 뺏어 칩 총량 보존이 깨진다 |
| 상대 스톱 체감 | **룰은 바꾸지 않는다.** 연출로 해결(GDD 미정 목록 등록) | 먼저 문턱을 찍은 쪽이 스톱하는 것이 옳은 플레이, 좌석마다 다른 룰은 SSOT를 흐린다 |

## 4. 검증 도구 (세션 스코프 — 재생성 필요)

Unity Test Runner 없이 도메인을 헤드리스로 검증하는 도구를 이 세션에서 만들어 썼다. **scratchpad에 있어 새 PC에는 없다.** 재작성 가치가 높다.

### 리플렉션 테스트 러너

`Temp/bin/Debug/*.Tests.dll`을 리플렉션으로 열어 NUnit 테스트를 직접 호출한다. **573건이 약 40초**에 돈다.

- 대상: `DoubleDown.Domain.Tests` · `Application.Tests` · `Infrastructure.Tests` (UnityEngine 비의존 3종)
- `Presentation.Tests`·`Integration.Tests`는 `UnityEngine.CoreModule`·`UniTask` 의존이라 **실행 불가** — 컴파일까지만 보장하고 Unity Test Runner로 넘긴다
- **핵심 함정**: 프로젝트 어셈블리를 `<Reference>`로 참조하면 빌드가 사본을 러너 폴더에 복사하고 `Assembly.LoadFrom`이 그 **낡은 사본**을 먼저 해석한다. `<Private>false</Private>` + `AssemblyResolve` 훅으로 `Temp/bin/Debug`에서 찾게 할 것
- 클래스별 실행 건수를 찍게 해 두면 "그 테스트가 정말 돌았나"를 매번 증명할 수 있다(통과는 출력되지 않으므로)

### 시뮬레이션 프로브

`MatchFlow` + `HeuristicAiPolicy`로 수천 판을 돌리며 이벤트 스트림에서 불변식을 전수 검사한다. `IEventSink` 구현 하나면 되고, `Pcg32RandomFactory`(Infrastructure)를 쓴다.

이번 세션 실적:
- **마지막 패 역전 분포** — 소진 승리 1,133판 중 32.4%가 "마지막 장에서 문턱 첫 돌파"
- **특수상황 미배선 발견** — 2,000시드에서 발생 0건 → 원인 확정
- **약탈 존 이동 불변식** — 4,294건 전수 위반 0

## 5. 함정 (이미 밟은 것 — 반복 금지)

### 이번 세션에서 새로 밟은 것

- **선택 인자가 미배선을 숨긴다**: `ISpecialSituationJudge`가 `= null` 선택 인자라 실게임 진입점이 안 넘겨도 컴파일이 통과했고, 판정기를 직접 꽂는 단위 테스트 60여 건은 전부 녹색이었다. **쪽·따닥·싹쓸이가 실게임에서 한 번도 발생하지 않은 채 잠복**했다. 새 축·판정기는 **필수 인자**로 넣어 컴파일러가 생산 지점 명부를 만들게 할 것.
- **`.csproj` 거짓 녹색**: 신규 `.cs`는 Unity 재임포트 전까지 `Compile Include`에 없어, 그 파일을 **아예 컴파일하지 않은 채** 0 오류로 통과한다. 신규 파일을 아무도 참조하지 않으면 영영 안 드러난다. 빌드 전에 `grep -F "<경로>" <csproj>`로 포함 여부를 확인할 것.
- **겹침과 간격 0은 다르다**: "애니메이션이 동시 진행되는 느낌"을 겹침으로 읽고 두 번 고쳤으나 실측은 겹침 0건 + 간격 0.2ms였다. 처방이 정반대(순서 강제 vs 시간 생성)다. **시간축 버그는 밀리초를 찍기 전에는 갈리지 않는다.**
- **없는 로그를 "그런 일이 없었다"로 읽지 말 것**: 상대 선언이 로그에 안 남아 "선언 없이 끝났다"고 오독했다. 실제로는 상대가 스톱을 불렀다.
- **`Screen Space - Overlay`는 소팅으로 못 이긴다**: 월드 스프라이트가 UI 뒤로 가는 문제를 소팅 레이어로 풀려다 오진했다. 실제 요구는 "위에 그리기"가 아니라 "**벗어나지 않기**"였다.

### 기존

- **생명주기 승격**: `MatchView`·`GoStopView`는 DDOL이라 **판보다 오래 산다**. 재시작 잔재 0은 파괴가 아니라 **상태 초기화**로 얻는다.
- **첫 진입 순서**: 씬은 **판을 먼저 세우고 UI를 나중에** 세운다. `BuildRuntime`의 `_view?.Bind(...)` 류 널 가드는 첫 판에서 조용히 지나간다 — `PrepareUiAsync`에서 보정 밀기를 반드시 함께 걸 것(`GoStopView.Bind`·판 창 정렬 둘 다 이 함정을 밟았다).
- **라운드 스코프 상태의 실제 수명**: 카드 인스턴스 id는 판마다 0부터 재사용된다. "라운드 스코프"라고 주석에 적힌 상태가 실제로 `Clear()`되는지 확인할 것(`_revealedDefinitions`가 안 씻겨 뒷면 카드가 앞면으로 샜다).
- **`ReleaseAll` 금지**: 전 뷰 파기라 로딩 커튼까지 죽인다. 씬 이탈은 `Close<T>()`.
- **stale `.csproj`**: asmdef 수정 후 Unity 재import 전까지 옛 참조다. CS0234는 코드가 아니라 이걸 의심하라.

## 6. 도달한 구조

```
IUIService (= UIManager)
 ├─ MatchView    계기판 — Render · UpdateScoreLines · ResetForNewMatch
 │   ├─ PlayWindow          판 가로 창 rect — 보드 정렬·축소의 SSOT
 │   ├─ EventBannerMotion   사건 채널 (IStepMotion) — 선언 배너
 │   ├─ HudRoundSummary     라운드 요약
 │   └─ HudRejectionFeedback 거부 흔들기
 └─ GoStopView   고/스톱 모달 + 키 힌트

StepPlayer (연출 재생)
 ├─ 스텝마다 WhenAll(자기 모션, 최소 박자)
 └─ 턴 경계: NotifyTurnBoundary → 렌더 → 시각 정착 펜스 → 턴 전환 쉼
      └─ BoardView.WaitForVisualQuiescenceAsync
           └─ CardView.TryDescribeUnsettled  4채널(지정 이동·뜸·뒤집기·추종)

BoardLayout (배치)
 └─ 모든 X가 PlayAreaHalfWidth 대칭에서 파생 — 실제 크기는 PlayWindow가 정한다
      루트 위치 = 창 중심, 루트 스케일 = min(1, 창 반폭 / 밴드 반폭)
```
