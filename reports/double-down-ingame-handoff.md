2026-08-30 갱신. 다른 PC에서 이어가기 위한 인수인계. 대상 저장소는 **Double Down** — 작업 브랜치는 **`master`**(`3f3dfa8`까지, 워킹트리 clean). `feature/floor-choice`는 `2d6791c`로 **병합 완료**라 더는 checkout 할 브랜치가 없다.

> **검증 루프가 코디네이터 안에서 닫힌다**: EditMode **836** + PlayMode **58**. 사용자 왕복 없이 수정→증명 사이클이 가능하고, "이 테스트가 정말 그 버그를 잡는가"까지 **뮤테이션 1줄 토글**로 기계 증명한다 — §4.
>

### 룰 (이번 세션에서 확정 — GDD §2-1-1에 반영됨)

| 항목 | 확정 내용 | 근거 |
|---|---|---|
| 고/스톱 제시 | **문턱 점수 하나**(기준선 7점) + 재선언 가드. 복수 라인·상대 우세는 **후반 조건부 페널티로 이월** | 초반에 강화가 없어 방어할 인플레도 없었다 |

| 소진 | 스톱 없이 패가 다 떨어지면 **항상 나가리** | 시뮬레이션 실측: 소진 승자 849판 **전부**가 이미 제시를 받았고 75%는 마지막 턴에도 받고 고를 택했다 — "물어보지도 못하고 끝나는" 판은 없었다 |
| 나가리 배판 | 다음 판 약탈액 **×2**, 연속이면 누적 곱. 배수는 **패자 칩 상한·bet_min 하한보다 앞에서** 곱한다 | 뒤에서 곱하면 가진 것보다 많이 뺏어 칩 총량 보존이 깨진다 |
| 상대 스톱 체감 | **룰은 바꾸지 않는다.** 연출로 해결(GDD 미정 목록 등록) | 먼저 문턱을 찍은 쪽이 스톱하는 것이 옳은 플레이, 좌석마다 다른 룰은 SSOT를 흐린다 |

## 2. ⚠️ 새 PC에서 첫 3분

1. **양쪽 저장소 pull** — 둘 다 `master`
2. **Unity 열고 컴파일 확인** — 에러 0건
3. **`tools/ddtest.sh` 경로 3줄 수정** — `SRC`·`DST`·`UNITY`. 그러면 836건이 13초에 돈다(§4)
4. **재생 검증 5종** — 이전 세션 수정분이 살아 있는지:
   - 다음 판으로 넘어갔을 때 더미·상대 손패가 **전부 뒷면**인가
   - 쪽/따닥/싹쓸이/뻑해소 시 **상대 획득패에서 피 한 장이 날아오는가**
   - 카드가 UI 패널에 **물리지 않는가** (콘솔에 `판을 N%로 축소해 창에 맞춘다` 정보 로그)
   - 마지막 패를 눌렀을 때 **치기 → 상대 턴 → 상대 획득 → 스톱 → 종료**가 순서대로 보이는가
   - **모든 패가 바닥을 경유하는가** — 특히 짝 없는 뒤집기가 획득 전에 바닥에 앉는가(2026-08-29 후반)
5. **택1 확인** — 바닥 짝이 2장 이상인 국면에서:
   - 후보 2장이 **창 한가운데 가로로 나란히** 펼쳐지는가 (원래 겹쳐 있던 후보도 분리되는가)
   - **확대된 그림 위에서 호버가 먹는가** (바닥 옛 자리를 더듬어야 하면 Offset 층 회귀 — §5)
   - 그림자가 카드를 **따라오는가**
   - 후보가 커진 채 유지되고 그 아래로 딤이 페이드 인 하는가 (커졌다 곧 작아지면 §5 수명 함정 재발)
   - 고르면 딤이 사라지고 카드가 **왔던 길 그대로** 내려가 획득 연출로 이어지는가
6. **선언 문구 확인** — 상대가 고를 외칠 때 판 중앙에 `FOE 1 GO!`가 뜨고 **판이 잠깐 멈춰 읽히는가**. 쪽이 나면 카드 위 `+1피`(수치)와 중앙 `JJOK! +1 PI`(사건)가 **함께** 뜬다(역할 분리, 의도된 그림)

### 다음 후보

- **⭐ 죽은 손잡이 정리 (가장 가까움)** — `TurnBeatBudget._choiceLiftFactor`(0.35)가 **아무것도 움직이지 않는다**. 택1 행의 Y 가 그 역할을 통째로 흡수했고 `CardHighlightProfile.ChoiceLiftFactor` doc 에 그 사실만 적어 둔 상태다. 제거하려면 프로파일 생성자·예산 자산까지 함께 손대야 한다
- **그림자 각도 테스트 공백** — 그림자가 카드를 따라가는 것은 계층이 보장하지만, **눕는 방향** 계산(Offset 변위를 더해 읽는 두 줄)은 전용 테스트가 없다. `FloorChoiceHitAreaTests` 옆이 그 자리다
- **택1 연출 수치 조정** — 지연 0.12s · 페이드 0.22s(`FloorChoicePopupView` 파일 상수) / 확대 1.25배(`TurnBeatBudget` 인스펙터) / 행 간격 `BoardLayout.ChoiceRowPitchFactor` **1.5 코드 상수** / 딤 0.55(프리팹 `Image_Dim`)
  - **확대 배수를 1.5 넘게 올리면 행 간격도 함께 올려야 한다.** 배치(`Board`)는 연출(`Playback`)을 참조할 수 없어 코드가 둘을 맞물릴 수 없고, 그 이음매는 `BoardLayoutTests` 가 문다(안 올리면 즉시 빨간불)
- **선언 문구 수치 조정** — `FloatingTextConfig` 의 `Declaration Scale`(3) · `Declaration Color`(흰색) · `Declaration Hold Seconds`(1). 마지막 값이 "읽을 시간"의 하한이다
- **`FloorChoicePopupView` 개명** — 실제 역할은 "막" 한 장인데 사본 시절 이름이 남았다. 타입명이 곧 Addressable 주소(`typeof(T).Name`)라 프리팹 이름 · 주소 등록(`UIAddressableRegistrar`) 동반 필요
- **턴 전환 연출** — 200ms 쉼이 그 자리다. "상대 차례" 표시, 상대 점수가 문턱에 가까워지는 긴장 고지, 스톱 선언의 타격감
- **설정 화면 ↔ 빠른 전투** — `TurnBeatBudget.SetFastBattle(bool)` 하나만 부르면 된다
- **막 표시 데이터화** — 이름·등급은 시트로 넘어갔다(§7). 프리팹 문구로 남은 것은 막 표시다

## 4. 검증 도구

배치 실행 스크립트는 **[`tools/ddtest.sh`](../tools/ddtest.sh)로 저장소에 커밋했다** — scratchpad는 세션과 함께 사라지므로(같은 PC에서도 사라졌다) 도구 자체를 남긴다. 경로 상수(`SRC`·`DST`·`UNITY`)는 이 PC 기준이라 **새 PC에서 그 세 줄만 고치면 된다**.

아래 함정 목록은 스크립트 주석에도 박혀 있다. 스크립트를 잃었을 때 재작성 비용의 대부분이 이 함정들이다.

### ⭐ Unity 배치 모드 실행 (주 도구 — `tools/ddtest.sh`)

**EditMode 836건이 13초.** `Presentation.Tests` 199건을 포함해 **모든 테스트를 실제로 실행**한다. Personal 라이선스로 동작하며 `unity` CLI 설치가 필요 없다.

```bash
bash tools/ddtest.sh                    # 전량 836건
bash tools/ddtest.sh --filter DoubleDown.Presentation.Tests    # 부분
bash tools/ddtest.sh --full-sync        # 사본 재생성 (Library 캐시 버림, 수 분)
```

**PlayMode 58건은 스크립트가 돌리지 않는다** — 필요하면 같은 사본에 `-testPlatform PlayMode` 로 직접 부른다. 택1 들어올림 수명·히트 영역이 거기 산다(§5 "EditMode 로 못 세우는 계약").

**⭐ `NUnit could not be found` 는 코드 오류가 아니다** — 사본의 패키지 캐시가 어긋난 것이다. 원본은 멀쩡한데 사본만 죽고, 에러가 테스트 파일 전체에 퍼지며 `Test`·`TestAttribute` 같은 애트리뷰트까지 못 찾는 모양이면 이 증상이다. `--full-sync` 한 번이면 끝난다. 이 세션에서 **두 번** 밟았다(며칠치 작업이 쌓인 뒤·asmdef 참조가 바뀐 뒤).

**구조** — 원본이 아니라 **사본**(`scratchpad/dd-batch`)에서 돈다:

```
SRC=C:/Unity_Projects/Double-Down
DST=<scratchpad>/dd-batch
UNITY="/c/Program Files/Unity/Hub/Editor/6000.3.19f1/Editor/Unity.exe"

# 1) Assets·Packages·ProjectSettings 만 증분 동기화 (Library 는 제외)
MSYS_NO_PATHCONV=1 robocopy "$(cygpath -w "$SRC/$d")" "$(cygpath -w "$DST/$d")" \
  /MIR /NFL /NDL /NJH /NJS /NP /R:1 /W:1

# 2) 실행 — -quit 을 주지 않는다
"$UNITY" -batchmode -nographics -projectPath "$DST" \
  -runTests -testPlatform EditMode \
  -testResults "$DST/results-editmode.xml" -logFile "$DST/batch.log"

# 3) results-editmode.xml 을 파싱해 어셈블리별 집계 + 실패 상세 출력
```

**재작성 시 반드시 지킬 것 — 다섯 함정을 전부 밟았다**

1. **`-quit` 금지.** `-runTests` 는 끝나면 스스로 종료한다. `-quit` 을 함께 주면 임포트 직후 종료해 **테스트에 도달하지 못하고 그때도 종료 코드 0** 을 낸다(성공으로 오인).
2. **사본에서 돌려야 한다.** Editor 가 원본을 `Temp/UnityLockfile` 로 잠그므로 같은 폴더를 배치 모드가 못 연다. 사본이면 작업 중 Editor 를 닫지 않아도 된다.
3. **`Library` 를 동기화에서 제외한다.** 사본이 쌓아 둔 임포트 캐시(약 2.2G)가 재임포트를 건너뛰게 하는 **자산**이다. 이것 하나가 5~10분을 13초로 줄인다.

**`-testFilter` 는 글롭이 아니라 .NET 정규식이다.** `Regex.IsMatch` 부분 일치라 와일드카드가 불필요하고, `*Foo*` 를 주면 `Quantifier {x,y} following nothing` 으로 파싱이 죽는다. 그러면 **결과 XML 이 안 생기고 프로세스는 조용히 종료**한다 — `-quit` 함정과 같은 계급의 무실행이다. 완료 판정은 프로세스 종료가 아니라 **XML 존재**로 한다.

```bash
-testFilter "FloorChoiceLiftLifetime"      # ✓ 부분 일치
-testFilter "*FloorChoiceLiftLifetime*"    # ✗ 정규식 파싱 실패 → 무실행
```

**행 판정 3지표** — 시동 직후 굳는 일회성 증상을 한 번 겪었다. 셋이 동시에 성립해야 "죽었다"로 본다: CPU ~0% + 로그 크기 정지 + **완주본 로그 크기 대비 미달**(정상 완주 ~96KB). 처방은 `pkill -9 -f "batchmode.*runTests"` 후 `Temp/UnityLockfile` 제거 뒤 재시도.

- **EditMode 로 못 세우는 계약이 있다**: 택1 변위 크기를 정하는 혼합값은 `CardView.LateUpdate` 만 굴린다. EditMode NUnit 은 플레이어 루프를 돌리지 않고 `ExecuteAlways` 도 없어 혼합값이 영원히 0 → 변위 0 → **질문 자체가 성립하지 않는다**. 리플렉션으로 사적 상태를 꽂으면 계약이 아니라 구현을 동결하게 된다. PlayMode 가 답이다.
- **계층을 바꾸면 `transform.Find` 가 조용히 null 이 된다**: `Find("Shake")` 는 **직속 자식만** 훑으므로 `Offset` 층이 끼어든 순간 죽는다. PlayMode 테스트라 EditMode 배치 실행이 못 잡는다 — 계층 변경 시 `Find` 경로 문자열을 grep 할 것.

### 이전 세션에서 밟은 것

- **선택 인자가 미배선을 숨긴다**: `ISpecialSituationJudge`가 `= null` 선택 인자라 실게임 진입점이 안 넘겨도 컴파일이 통과했고, 판정기를 직접 꽂는 단위 테스트 60여 건은 전부 녹색이었다. **쪽·따닥·싹쓸이가 실게임에서 한 번도 발생하지 않은 채 잠복**했다. 새 축·판정기는 **필수 인자**로 넣어 컴파일러가 생산 지점 명부를 만들게 할 것.
- **`.csproj` 거짓 녹색**: 신규 `.cs`는 Unity 재임포트 전까지 `Compile Include`에 없어, 그 파일을 **아예 컴파일하지 않은 채** 0 오류로 통과한다. 신규 파일을 아무도 참조하지 않으면 영영 안 드러난다. 빌드 전에 `grep -F "<경로>" <csproj>`로 포함 여부를 확인할 것.
- **겹침과 간격 0은 다르다**: "애니메이션이 동시 진행되는 느낌"을 겹침으로 읽고 두 번 고쳤으나 실측은 겹침 0건 + 간격 0.2ms였다. 처방이 정반대(순서 강제 vs 시간 생성)다. **시간축 버그는 밀리초를 찍기 전에는 갈리지 않는다.**
- **없는 로그를 "그런 일이 없었다"로 읽지 말 것**: 상대 선언이 로그에 안 남아 "선언 없이 끝났다"고 오독했다. 실제로는 상대가 스톱을 불렀다.
- **`Screen Space - Overlay`는 소팅으로 못 이긴다**: 월드 스프라이트가 UI 뒤로 가는 문제를 소팅 레이어로 풀려다 오진했다. 실제 요구는 "위에 그리기"가 아니라 "**벗어나지 않기**"였다.
- **Mono `string.Format` 의 마지막 자리표시자**: 닫는 이스케이프 `}}` 에 인접한 자리표시자의 서식 지정자를 **리터럴로 흘린다**(`{1:F9}` → `"F9"`). `{0:F9}` 는 정상이라 서식 종류를 의심하게 되는데 원인은 **위치**다. JSON 을 조립할 때는 `string.Format` 대신 `ToString("F9", InvariantCulture)` + 문자열 연결을 쓴다. 이 진단에 두 번 실패했고, **실제 문자열을 로그로 찍은 한 줄이 끝냈다**.
- **초록불이 검증을 뜻하지 않는다**: `OpponentHand_MirrorsPlayerFan_WithFlippedSign` 은 한 번도 실패한 적 없으면서 회전·아치가 0이라 `0 == -0` 을 비교하고 있었다. 설정값을 끄면 그 값을 재던 테스트가 **공허하게 통과**한다 — 값을 끌 때는 그것을 검증하던 테스트가 무의미해지지 않았는지 함께 본다.
- **설정 기본값을 동결하는 테스트는 소리 없이 낡는다**: `ScriptableObject.CreateInstance<T>()` 를 쓰는 테스트는 `.asset` 이 아니라 **C# 필드 기본값**을 잰다. 자산과 코드 기본값을 함께 바꾸면 이 테스트만 남겨진다(획득패 배율 0.5 → 0.53 에서 2건이 그렇게 깨졌다).
- **넓은 가드를 좁힐 때는 그 가드가 막던 실제 문제를 먼저 찾는다**: `StepPlayer` 의 폴드 가드가 `RoundEnded` 까지 막아 마지막 수 연출을 버리고 있었다. 가드만 좁히면 그 가드가 막던 **권위 대조 오판**("권위에 없는 카드" — 라운드 밖 권위는 빈 목록이다)이 되살아난다. 넓은 가드를 **좁은 면제**로 바꿔야 했고(대조 생략 + 끝 렌더 생략), 그 선례가 이미 `PlaySplitAtDealAsync` 에 있었다. **가드에 이유가 주석으로 적혀 있어서 발견했다** — 없었으면 옛 버그를 되살렸을 자리다.

### 기존

- **생명주기 승격**: `MatchView`·`GoStopView`는 DDOL이라 **판보다 오래 산다**. 재시작 잔재 0은 파괴가 아니라 **상태 초기화**로 얻는다.
- **첫 진입 순서**: 씬은 **판을 먼저 세우고 UI를 나중에** 세운다. `BuildRuntime`의 `_view?.Bind(...)` 류 널 가드는 첫 판에서 조용히 지나간다 — `PrepareUiAsync`에서 보정 밀기를 반드시 함께 걸 것(`GoStopView.Bind`·판 창 정렬 둘 다 이 함정을 밟았다).
- **라운드 스코프 상태의 실제 수명**: 카드 인스턴스 id는 판마다 0부터 재사용된다. "라운드 스코프"라고 주석에 적힌 상태가 실제로 `Clear()`되는지 확인할 것(`_revealedDefinitions`가 안 씻겨 뒷면 카드가 앞면으로 샜다). **2026-08-29 후반**: 모든 패가 공개와 동시에 바닥으로 나가면서 "공개됐는데 아직 숨김 존에 있는 카드"가 구조적으로 사라져, 스냅샷 마스킹 예외를 걷어냈다 — 그 버그 부류가 이제 불가능하다. 다만 **공개 맵 자체는 살아 있다**: 변환기가 획득 카드의 원형 id 를 복원하는 데 쓴다(`CardsCapturedEvent` 가 인스턴스 id 만 싣는다). 지웠으면 획득 집계가 조용히 0 이 될 뻔했다.
- **`ReleaseAll` 금지**: 전 뷰 파기라 로딩 커튼까지 죽인다. 씬 이탈은 `Close<T>()`.
- **stale `.csproj`**: asmdef 수정 후 Unity 재import 전까지 옛 참조다. CS0234는 코드가 아니라 이걸 의심하라.
