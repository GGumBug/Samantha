# Double Down 초반 벽 구현 계획: 「밑천 내기」

2026-10-05. [벽 설계 문서](double-down-wall-design.md)의 권고를 Double Down 저장소에 넣는 계획이다.
결정 1(3판 제한 폐지)과 결정 2(딴 돈 따로 쌓기)가 확정된 상태를 전제로 한다.
2026-10-06 사용자가 판돈과 상점에서 쓰는 돈을 분리하기로 해서 그 규칙을 반영했다(§1-2).

이 계획은 게임 코드를 열지 않고 썼다. Double Down 저장소는 이 프로젝트에서 닿지 않는다.
좌표(`파일:줄`)는 전부 [인게임 핸드오프](double-down-ingame-handoff.md)와 설계 문서에서 옮긴 것이다.
착수할 때 각 좌표를 실제 파일에서 다시 확인한다. 표기는 설계 문서와 같다. [코드]는 문서가 인용한 좌표이고 [추정]은 짐작이다.

## 0. 한 장 요약

- 최소 버전은 규칙 넷을 도메인에 넣고, 실제 엔진에서 재고, 화면에 "남은 밑천"을 그리는 데까지다.
- 단계는 다섯이다. 공통 수리, 도메인, 판정, 화면, 문서다. 부품(꽁지 한 번 등)은 결정 3~5가 서야 착수한다.
- 상태는 좌석마다 하나만 더한다. "이 선수전에서 잃은 칩 누계"다. 칩 칸을 둘로 쪼개지 않는다.
- 상대 AI는 바꾸지 않는다. 새 종료 종류도 없다.
- 런 계층은 칩 하나를 최대 밑천과 골드 둘로 가른다(§1-2). 판 안의 규칙과 단계 0~1의 정산 작업은 분리와 무관하다.
- 실제 엔진 클리어율이 재생값 66.4%의 ±2%p 안에 들어야 화면 단계로 간다. 아니면 시트 키를 끄고 원인부터 본다.
- 이기면 최대 밑천이 상대 밑천만큼 오른다(2026-10-06 사용자 확정, §5 질문 10). **2026-10-07 철회**, [밑천 업그레이드 계획](double-down-stake-upgrade-plan.md)이 잇는다.
  밑천이 커지는 길이 측정 때와 같아 66.4%를 재측정 없이 쓴다. 착수를 막는 사용자 결정은 남지 않았다.
- 크기는 설계 문서의 추정을 따른다. 최소 버전 8~10일, 완성 16~20일이다 [추정].

## 1. 규칙을 상태로 옮기기

설계 문서 §5-1의 규칙 넷을 좌석별 값 셋으로 표현한다.

| 값 | 뜻 | 어디서 오는가 |
|---|---|---|
| `stake` | 그 선수전에 들고 앉은 칩 | 선수전 시작 시 칩. 이미 있는 값이다 |
| `lost` | 그 선수전에서 잃은 칩 누계. 줄지 않는다 | **새로 더하는 유일한 상태** |
| `chips` | 지금 칩 | 이미 있는 흐름의 칩이다 |

나머지는 파생한다. SSOT를 지키려고 따로 저장하지 않는다.

- 남은 밑천 = `stake − lost`
- 딴 돈 = `chips − (stake − lost)`

한 판의 정산은 이렇게 바뀐다. 기존 약탈액 계산과 배수 적용은 그대로 둔다.

```
이전액 = min(약탈액, 승자.stake × 한도 배수, 패자.stake − 패자.lost)
패자.lost += 이전액
패자.stake − 패자.lost == 0 이면 선수전 종료. 패자의 남은 칩(딴 돈 포함)을 전부 승자에게 옮긴다
```

- 규칙 1(들고 온 만큼만 딴다)이 둘째 항이다. 규칙 3(밑천이 마르면 진다)이 셋째 항과 종료 조건이다.
- 규칙 2(딴 돈은 따로)는 `lost`가 이겨도 줄지 않는다는 성질로 성립한다.
- 규칙 4(털면 다 가져온다)는 종료 시 이전이다. 칩 총량은 그대로 보존된다.

### 1-1. 플레이어에게는 HP로 보인다

2026-10-05 사용자가 밑천을 최대 HP로 읽자고 제안했다. 위 상태와 그대로 맞물린다.

| 상태 | HP로 읽으면 |
|---|---|
| `stake` | 최대 HP. 선수전 동안 바뀌지 않는다 |
| `stake − lost` | 지금 HP. 한 판 지면 이전액만큼 깎인다 |
| 딴 돈 | HP 바 밖에 쌓이는 칩. HP를 최대 위로 올리지 않는다 |
| 선수전 종료 | 상대 HP가 0이면 이긴다. 상대가 쌓아 둔 딴 돈(내가 뺏긴 칩 포함)을 되찾는다 |

설계 문서의 약점 "칩이 있는데 왜 끝났나"에 HP 바가 바로 답한다. 화면 단계는 이 그림으로 짓는다(2-2).
이긴 판에서 내 HP가 차오르는지는 §5 질문 9가 다룬다. 확정된 결정 2와 계획은 차오르지 않는 쪽이다.

### 1-2. 판돈과 골드를 나눈다

2026-10-06 사용자가 판돈과 상점에서 쓰는 돈을 완전히 나누기로 했다. 칩 하나가 HP와 지갑을 겸하면 직관적이지 않다는 까닭이다.
런이 들고 다니는 칩 하나를 둘로 가른다.

| 런 상태 | 뜻 | 바뀌는 때 |
|---|---|---|
| 최대 밑천 | 다음 선수전의 `stake`. 선수전은 언제나 HP가 가득 찬 채로 시작한다 | 상점 구매로만 오른다([밑천 업그레이드 계획](double-down-stake-upgrade-plan.md)). 질문 10의 성장은 2026-10-07 철회 |
| 골드 | 상점에서만 쓰는 돈. HP와 무관하다. 가칭이다(질문 12) | 이기면 상대 밑천만큼 들어온다(질문 11). 상점에서 쓰면 준다 |

- 판 안은 §1 그대로다. 선수전이 끝나면 판 안의 `chips`를 버리고 위 두 값만 갱신한다.
- 분리해도 잃는 긴장이 적다. 규칙 4 때문에 이긴 선수전은 언제나 내 밑천이 가득 찬 채로 끝나고, 진 칩이 다음 선수전으로 넘어오는 일이 이미 없다.
- 최대 밑천이 1,200 → 1,650 → 2,100 → 2,900으로 오르면 상점에서 아무것도 사지 않는 런이 측정 조건과 같다. 그래서 66.4%가 그대로 유효하다.
- 1,200에 고정하면 타짜가 나를 KO 시키는 데 4승이 아니라 2승이면 된다. 판 승률만 넣은 단순 경주 모형으로 1막 40%대다 [추정].
- 핸드오프 §1 데이터 표의 확정 결정 "칩은 매치 사이 이월"을 고친다. 그 근거였던 위험 축은 규칙 4가 이미 지웠다.

기존 순서와의 관계가 이 계획에서 가장 조심할 자리다.

| 기존 장치 | 지금 위치 [코드] | 새 규칙에서 |
|---|---|---|
| 나가리 배판 ×2, 폭탄 ×2ⁿ | 패자 칩 상한·`bet_min` 하한보다 **앞** | 그대로 앞에 둔다. 한도보다 뒤에서 곱하면 총량 보존이 깨진다 |
| `bet_min` 하한 | 상한 앞 | 남은 밑천보다 클 수 없다. 하한을 건 뒤 한도로 자른다 |
| 패자 칩 상한 | **맨 마지막** | "패자 남은 밑천" 한도로 바꾸되 맨 마지막 자리를 지킨다 |
| 개평꾼(진 판 이전액 9/10) | 이전액에 곱한다 | 밑천이 0이 되지 않는다. 최소 버전은 매대에서 빼고 완성 버전에서 순서를 한도 앞으로 옮긴다 |
| 소금·거울(박 맞은 판 1/2, 2/3) | 이전액에 곱한다 | 개평꾼과 같은 계급이다. 실제 엔진 판정에서 12판 안에 끝나는지 본다 |

패자 칩 상한을 맨 마지막에 두는 것은 디버그 모드의 안전 근거이기도 하다.
"이 선수 승리" 문은 정산을 한 번 더 부르는데, 마지막 상한이 이중 정산을 0으로 만든다 [코드: 핸드오프 §4 디버그 모드].
새 한도가 이 자리를 잃으면 디버그 문이 칩을 두 번 옮긴다.

## 3. 단계

### 단계 0: 측정 경로 수리 (1.5~2일)

| # | 할 일 | 합격 기준 |
|---|---|---|
| 0-1 | `LootSettler.cs:502-516`을 열어 4판 이상에서 죽는 까닭을 확인하고 고친다 | 판 상한 12에서 HeadlessSim 5,000시드가 예외 없이 돈다 |
| 0-2 | 사다리 스윕의 판 축 격자를 판 상한에서 파생한다 | 판 상한 12에서 `IndexOutOfRange` 0건 |
| 0-3 | 스윕과 시뮬의 덱 렌즈 세 자리를 함께 고친다 | 정산과 AI 평가가 같은 덱으로 접힌다 |
| 0-4 | 스윕 시드에 판 순번을 넣는다 | 재대결을 넣을 때 같은 판이 반복되지 않는다 |
| 0-5 | 새 기준선을 잰다. 규칙은 그대로, 판 상한 3 | 사다리 스윕 11.3% 근처가 다시 나온다 |

- 0-3은 덱빌딩 1-0의 ②와 같은 작업이다. 핸드오프가 "도장과 무관하게 값이 있다"고 적었으므로 덱 결정을 기다리지 않는다.
- 0-4는 재대결(꽁지 한 번)을 넣지 않으면 미뤄도 된다. 다만 스윕을 여는 김에 같이 하는 편이 싸다.
- 0-5의 기준선이 이후 모든 대조의 출발점이다. 골든 숫자는 단계 1에서 한 번만 다시 뜬다.

### 단계 1: 도메인만 (2~3일)

화면은 손대지 않는다. 시트 키로 켜고 끈다.

| # | 할 일 | 합격 기준 |
|---|---|---|
| 1-1 | BGDatabase 에디터에서 키 둘을 더한다. 규칙 스위치(0/1), 한도 배수(bp, 10000) | 시트가 유일 출처다. 21키 규칙을 따른다 |
| 1-2 | 밸런스 타입에 새 키를 **필수 인자**로 더하고 생산 지점을 전수로 채운다 | 생산 지점 표의 "새 축" 열이 빈 행 0 |
| 1-3 | 좌석 상태에 `lost`를 더하고 선수전 시작에 0으로 둔다 | 재대결 없이도 선수전마다 초기화된다 |
| 1-4 | `LootSettler` 이전액 식에 한도 둘을 넣는다. 순서는 §1 표 | 스위치 0이면 기존 시험이 비트 단위로 같다 |
| 1-5 | 종료 판정을 밑천 소진으로 바꾸고 종료 시 잔여 이전을 넣는다 | 칩 총량 불변식 위반 0건(시뮬레이션 프로브) |
| 1-6 | 개평꾼을 매대 추첨 풀에서 뺀다 | 스위치 1일 때만 뺀다 |
| 1-7 | 판 상한 시트 값을 12로 올린다 | 12판 도달 시 기존 처리 그대로. 도달 횟수를 센다 |
| 1-8 | `RunFlow`를 최대 밑천과 골드로 가르고 `ShopSession`의 세 SKU를 골드에 잇는다 | 상점에서 써도 다음 선수전의 `stake`가 그대로다 |
| 1-9 | 선수전 승리 시 최대 밑천과 골드를 갱신한다 | 상점 없는 런의 밑천 수열이 1,200 → 1,650 → 2,100 → 2,900이다 |

검증은 [evaluation.md](../.claude/rules/evaluation.md)의 두 겹 루프를 따른다.

- **단위 시험.** 설계 문서의 예를 손계산 동결 케이스로 둔다. 1,200 대 호구 450에서 450 · 450 · 300으로 지는 경우가 하나다.
  두 판 지고 한 판 이겨 900과 450을 함께 가져오는 경우가 둘째다. 나가리 배판과 폭탄이 한도 앞에서 곱해지는 경우가 셋째다.
- **뮤테이션은 규칙마다 하나.** 각 규칙을 걷어낸 상태가 "그 규칙이 없던 시절의 코드"가 되게 한다.
  설계 문서 §5-3의 제거 실험이 방향을 알려 준다(판 상한 복원 37.0%, 규칙 1 제거 33.9%, 규칙 2 제거 55.8%, 규칙 4 제거 49.8%).
- **골든 시험.** 정산식이 바뀌므로 골든 숫자가 움직인다. 이 커밋에서 한 번만 다시 동결한다.
- **커밋 단위.** 1-1과 1-2(키), 1-3~1-5(정산과 종료), 1-6(매대), 1-7(시트 값), 1-8과 1-9(런 분리)를 따로 커밋한다. 각각 revert 가능하게 둔다.
- **런 분리도 같은 스위치 아래 둔다.** 스위치 0이면 칩 하나를 이월하는 지금 런이 그대로 돈다.

### 판정: 실제 엔진 값 (반나절)

스위치를 켜고 사다리 스윕 2,000런을 돌린다. 설계를 다시 재는 일이 아니라 구현이 재생값을 내는지 확인하는 일이다. 아래 다섯을 표로 남긴다.

| 확인 | 합격 기준 | 어긋나면 |
|---|---|---|
| 1막 클리어율 | 66.4% ± 2%p | 스위치를 끄고 재생기와 엔진의 차이를 찾는다 |
| 가장 긴 선수전 | 재생값 8판 근처, 12판 도달 0 | 소금·거울 경로부터 본다 |

## 6. 되돌리는 길

- 단계 1이 끝나면 규칙 스위치 하나로 지금의 규칙(판 상한 3, 칩 하나 이월)으로 돌아간다. 시트 값만 바꾸면 된다.
- 판정에서 어긋나면 스위치를 끄고 머지한 채로 둔다. 단계 0의 수리는 그대로 값이 있다.
- 화면 단계는 스위치와 무관하게 그려져야 한다. 스위치가 0이면 남은 밑천 = 지금 칩으로 보이면 된다.

  그래서 `Chips = 최종 칩` 한 줄은 그대로 두고 골드에 `최종 칩 − 들고 앉은 칩`을 더한다. 더한 값이 음수면 칩 보존 위반으로 던진다.
- 계획 1-8·1-9의 합격 기준은 시험이 고정한다. 상점에서 써도 다음 매치 시작 칩이 그대로다(`ShopFactoryWiringTests`). 밑천 수열 1,200 → 1,650 → 2,100 → 2,900과 골드 0 → 450 → 900 → 1,700(`RunFlowTests`).
- 단계 1은 여기서 닫힌다. 화면은 아직 칩 하나를 보이므로 스위치는 단계 2 마지막 카드까지 꺼 둔다. `ShopView`는 `ShopSession.Purse`를 읽어 꺼진 런에서는 지금과 같은 값을 보인다.
