### 런 계층 (2026-08-31, master)

판과 판 사이가 비어 있던 자리에 사다리가 섰다. 계층은 **Domain 상태 기계 → Boot 진행 소유자 → 표현**이고, 씬 계층은 `DoubleDown.Domain` 을 참조하지 않아 런 진행이 Boot 에서 끝난다(그래서 `ReportMatchEnded` 가 `bool` 을 돌려준다).

**설계 판단 둘**:
- **잊으면 안 되는 이음매는 "공장이 런을 아는 것" 하나**다. 그래서 런이 공장의 **필수 인자**이고, `MatchFlow` 는 손대지 않았다. 새 축을 필수 인자로 넣으면 컴파일러가 호출처 명부를 만들어 준다
- **두 축을 합치지 않는다** — `_nextMatchIndex`(재현/시드)와 `RunFlow`(게임/사다리). 런이 새로 서도 지수는 리셋하지 않는다. 되돌리면 새 런이 이전 런과 **같은 판을 재현**한다

### 후반 (턴 재구성·텍스트 통합·택1 행)

- **⭐ 종단 상태가 같아도 경유 경로는 틀릴 수 있다**: 따닥에서 뒤집은 패가 바닥을 거치지 않고 더미에서 획득패로 직행했다. 어떤 테스트도 잡지 못했다 — 턴이 끝나면 그 카드는 양쪽 다 획득패에 있어 시작·끝 상태 비교가 전부 통과한다. 처방은 **폴드 중간 상태를 재는 테스트**(`PresentationBoardModelTests` 의 경유 검사)다.
- **⭐ 한 필드가 두 의미를 지면 갈라지는 날 조용히 틀린다**: `DrawCardFlippedStep.IsChoicePending` 이 판정 사실과 연출 계획을 겸했다. 따닥 병합으로 둘이 갈라지자 폴드가 오판했다. 처방은 두 번째 의미를 별도 축으로 선언(`AwaitsFloorChoice`). → [dual-meaning-field-split](../best-practice/dual-meaning-field-split.md)
- **⭐ 같은 축이라도 크기가 종류를 바꾼다**: 택1 변위를 펀치와 같은 `Shake` 층에 얹었더니 호버와 그림자가 따라오지 않았다. 펀치는 몇 픽셀 진동, 택1은 카드 폭의 몇 배 — **표면적 유사성이 명시된 규칙("지속 상태는 루트, 과도 채널은 Shake")을 이겼다.** 처방은 지속 변위 전용 `Offset` 층 신설.
- **`[SerializeField]` 를 초기값 없이 추가하면 조용히 죽는다**: `.asset` YAML 에 없는 필드는 C# 초기값이 유일한 값이다. 없으면 `0`/검정이 되어 컴파일·테스트는 통과하는데 화면에서만 사라진다.
- **EditMode 로 못 세우는 계약이 있다**: `CardView.LateUpdate` 만 굴리는 혼합값은 EditMode 에서 영원히 0 — 질문 자체가 성립하지 않는다. PlayMode 가 답이다.
- **계층을 바꾸면 `transform.Find` 가 조용히 null 이 된다**: `Find("Shake")` 는 직속 자식만 훑으므로 층이 끼어든 순간 죽는다. 계층 변경 시 `Find` 경로 문자열을 grep 할 것.

### 전반 (택1 팝업)

- **⭐ 수명이 다른 두 상태를 같은 해제 지점에 묶지 말 것**: `CancelAll`(스텝 수명)에 택1 들어올림 해제(국면 수명)를 얹어, 사람이 고르기 전에 후보가 커졌다 곧 꺼졌다. 짧은 수명이 긴 수명을 자른다 — 시간축 시나리오에서만 드러난다.
- **호출처 탐색을 한 파일 안에서 닫지 말 것**: 1차 진단이 파일 안 호출만 찾아 절반만 맞았다. 진짜 목은 파일 밖(`StepPlayer`)에 있었다. 검증자 위임 프롬프트의 "내 기대 시나리오도 틀릴 수 있다"가 잡았다.
- **`Editor.log` 의 `error CS` 는 낡은 잔재일 수 있다**: 판정 순서는 ① DLL mtime ② 에러의 파일 분포(어셈블리 단위 컴파일이라 "에러가 파일 A 하나뿐"이면 같은 어셈블리 나머지는 통과).
- **`Screen Space - Overlay` 는 월드 스프라이트를 항상 덮는다 → 연쇄 결정을 만든다**: 캔버스를 Camera 로 내리면 연쇄가 통째로 사라지고 실물 카드를 그대로 승격할 수 있다.
- **구현 시작 전에 "이미 있는 축"을 먼저 grep 할 것**: 택1 팝업을 사본 방식으로 절반 만든 뒤에야 `SetChoiceCandidate` + `ApplyChoiceLift` 가 이미 있었음을 발견했다.
- **절단 재개 시 상태 판별 3지표**: `git status --short` + 파일 mtime + 산출물 grep. 병행 작업이 있으면 mtime 순서가 저자를 가른다.
